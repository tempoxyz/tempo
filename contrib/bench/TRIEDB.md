# Native Monad TrieDB experiment

The `monad-triedb` Cargo feature enables the experimental Reth storage adapter
for plain/hashed account and storage records. It is off by default. Ethereum
state-root computation, trie-node tables, history, and consensus are unchanged.
This is a storage-backend experiment, not a port of Monad's full execution engine.

Build the native library using the [pinned Reth adapter instructions](https://github.com/paradigmxyz/reth/blob/c6bbfb47bbb91f837e74e293de751ebded0be5bd/crates/storage/db/native/triedb/README.md).
The native library is GPL-3.0-or-later. The adapter is not production-ready;
review its retention, backup, error handling, and cursor limitations before use.

## Benchmark setup

Use `bench-e2e.nu`, the same single-runner harness used by `bench-e2e.yml`, with
the existing `public-mix` preset. It runs two local validators with disjoint
16-thread CPU sets and a 60 GiB memory limit each. This is not the ten-validator
multi-region topology. The preset is 80% TIP20 transfers, 5% mints, and 15% MPP
channel opens, targeting prepopulated state; zero-bloat runs are invalid.

Requirements include 32 logical CPUs, enough RAM for both validators, Node 24,
Nushell, `txgen-tempo`, `bench`, and optionally Samply. Install both stable and
nightly Rust; use nightly for formatting and Clippy. Keep the native huge-page
reservation identical for baseline and feature measurements.

Use one NVMe filesystem for the MDBX datadirs, snapshots, and benchmark output.
Reserve another unmounted NVMe for TrieDB and divide it into two partitions,
one per validator. Do not use an OS/RAID member. Identify devices by their
serial numbers before creating filesystems or partitions.

**`RETH_TRIEDB_INITIALIZE=1` discards the entire configured native device.** Use
only disposable data and explicit device paths. Do not point both validators
at the same partition. Preserve the original MDBX snapshots for rollback.

```sh
# Set these to verified, dedicated, unmounted partitions and a built library.
: "${TRIEDB_A_DEVICE:?}" "${TRIEDB_B_DEVICE:?}" "${RETH_TRIEDB_LIBRARY:?}"
: "${BASELINE_SHA:?}" "${FEATURE_SHA:?}"
export BENCHMARK_ID=monad-triedb-comparison

feature_env="RETH_TRIEDB_LIBRARY='$RETH_TRIEDB_LIBRARY' RETH_TRIEDB_INITIALIZE=1 RETH_TRIEDB_MAP='/reth-bench-a=$TRIEDB_A_DEVICE;/reth-bench-b=$TRIEDB_B_DEVICE'"

nu bench-e2e.nu e2e \
  --baseline "$BASELINE_SHA" --feature "$FEATURE_SHA" \
  --feature-features monad-triedb --feature-env "$feature_env" \
  --preset public-mix --bloat 100 --duration 90 --tps 50000 \
  --accounts 1000 --max-concurrent-requests 5000 --run-pairs 3 \
  --samply --no-upload-profiles --runner-metrics-url ''
```

First run the same configuration with both refs set to the baseline and no
feature feature/env flags to measure noise. Start with `--bloat 1 --run-pairs 1`
for a functional smoke test; a RAM-resident 1 GiB dataset does not establish a
large-state NVMe performance advantage. Initial snapshot generation and native
migration are outside the timed load interval but may be lengthy on fresh boxes.

Use `bench-results/*/summary.json` for verdicts. Retain logs, profiles, exact
commit IDs, compiler/feature settings, device layout, and binary hashes. Report
dataset size and topology alongside any numbers; do not equate local results
with the multi-region benchmark.

For isolated boxes, `TEMPO_BENCH_BINARY_CACHE` can point at a read-only local
binary cache. Place already-built binaries under
`<cache>/<profile>/<commit-and-feature-cache-key>/tempo`, using the same key as
the existing remote cache. Default-feature builds use the full commit SHA;
nondefault feature sets include the feature suffix generated by
`bench-cache-key` in `tempo.nu`. Populate it only from the corresponding build.
`--no-upload-profiles` leaves Samply profiles local instead of publishing them.
