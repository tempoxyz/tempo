# TIP-1086 receipt-gas measurements

Measured 2026-09-11 for [PR #7506](https://github.com/tempoxyz/tempo/pull/7506), stacked on the configurable-account activation [PR #7581](https://github.com/tempoxyz/tempo/pull/7581), base commit [867dd8eee880448edf428858e8c5dd7630c41e74](https://github.com/tempoxyz/tempo/commit/867dd8eee880448edf428858e8c5dd7630c41e74).

Carried grants remove immutable permission storage, not spending accounting. In the existing-account, primitive-secp256k1, sender-paid two-cap/two-target example, first use falls from **2,817,105 to 312,397 gas (88.91%)**, with **11 versus 1** newly nonzero keychain words. Subsequent identical uses cost **43,405 versus 65,197 gas**: stored mode becomes cumulatively cheaper at use **116**. These are executed handler receipts under this draft's proposed pricing, not a production deployment or a claim that carried grants beat every alternative.

[Cost plots and mode-selection analysis](tip-1086-cost-decisions.md) compare first use,
reuse, sponsorship, batches, configurable accounts, and Privy's advertised paid-signature
reference. The [two-page PDF](tip-1086-plots.pdf) and [288-scenario comparison CSV](tip-1086-comparisons.csv)
are reproducible with `uv run scripts/plot-tip-1086.py`. The analysis rounds each transaction's
fee separately: the example's fee crossover is use **116** at the TIP-1067 cap
(**117** at the original fixture/floor price), versus use **116** for gas.

## Data and scope

- [Gas matrix](tip-1086.csv): **1,728 executions**, covering 3 parent curves × 3 delegate curves × primitive/configurable parent × primitive/configurable delegate × sender/sponsor fees × 4 policies × stored/carried mode × 3 phases.
- [Boundary/setup cases](tip-1086-edges.csv): maximum-length WebAuthn, two eight-owner quorums, 32-call batches, 120-recipient scopes, fresh accounts, fresh configurable accounts, warmed counter access lists, and first use in a later signed period.
- [Failed execution](tip-1086-failures.csv): **24 executions** covering scope rejection, explicit revert, and out-of-gas, with primitive/configurable accounts and sender/sponsor fees in both modes.
- Encoding unit tests exercise exact **1,024 / 1,025 / 4,096 / 4,097-byte** certificate boundaries; the first two also assert payment/general classification. The bound applies to the whole signed certificate.

The matrix is exhaustive over these listed fixture dimensions, not every possible policy, signature, call graph, chain state, or competing product. Smart-account alternatives on other chains, vendor/relay charges, network propagation, and end-to-end production throughput are not measured.

## Primitive parent and delegate

Both use secp256k1. First use includes authorization plus one token transfer in the same transaction; reuse omits the stored authorization but retains the carried certificate.

|---|---|---:|---:|---:|---:|---:|
| Unlimited | Sender | 300,218 | 44,842 | 36,518 | 44,842 | 32 |
| 1 lifetime cap | Sender | 802,905 | 311,369 | 39,205 | 64,169 | 21 |
| 1 periodic cap | Sender | 803,005 | 314,065 | 39,305 | 66,865 | Window-dependent |
| 2 caps + 2 targets | Sender | 2,817,105 | 312,397 | 43,405 | 65,197 | 116 |
| Unlimited | Sponsor | 305,018 | 49,542 | 41,318 | 49,542 | 33 |
| 1 lifetime cap | Sponsor | 807,705 | 307,615 | 50,805 | 58,315 | 68 |
| 1 periodic cap | Sponsor | 807,805 | 309,957 | 50,905 | 60,657 | Window-dependent |
| 2 caps + 2 targets | Sponsor | 2,821,905 | 308,643 | 55,005 | 59,343 | 581 |

“Stored cheaper from use” counts the first transaction and assumes identical subsequent state/call costs, unchanged policy, no revocation, and no window rollover. With first-use saving `S` and positive carried repeat premium `D`, the first strictly cheaper stored total is `floor(S / D) + 2`. Different calldata, signatures, account state, or credit balances can change the threshold.

At the fixture price of **600,000,000 attodollars/gas**, the sender-paid two-cap/two-target first transactions charge **0.001691 versus 0.000188 pathUSD**, including micro-unit rounding. This is an explicit test price, not a live fee quote. Conversion is `ceil(gas × 600000000 / 10^12) / 10^6`, using the protocol fee conversion.

The default cost model now reprices those fixed gas receipts at the
[TIP-1067](../../tips/tip-1067.md) **12,000,000,000 attodollars/gas cap**, with zero
priority fee: **0.033806 versus 0.003749 pathUSD** on first use and **0.000521
versus 0.000783 pathUSD** on reuse. This is 20× the fixture price before rounding;
the original executed receipts below remain unchanged. The
[repriced CSV](tip-1086-repriced.csv) preserves both floor and cap costs for all
1,784 rows and leaves rejected setups unpriced. This is a model with fixed state
paths, not a new execution at cap pricing or a live basefee measurement.

## Periodic accounting

The signed carried period is anchored at `validAfter = 100`; fixtures use a 60-second period, first/repeat timestamp 125, and rollover timestamp 200. For primitive sender-paid transactions, the rollover costs **39,305 stored versus 316,965 carried gas**. With a sponsor, it costs **53,705 versus 312,857 gas**.

A carried periodic counter uses separate spent and window words. Its first window has implicit index zero; entering the first nonzero window creates the window word. This one-time creation is not a recurring charge on every later rollover. Stored mode uses its existing packed/reset accounting and its existing window anchor. Therefore do not extrapolate lifetime-policy break-even counts to periodic grants.

## Method

The fixture executes real signed Tempo transactions through `TempoHandler`, finalizes the journal, and commits between phases. It verifies primitive secp256k1, P256 and WebAuthn signatures and configurable owner quorums; every attached authorization first round-trips through its real RLP decoder. Receipts must succeed for success rows. Failure rows must fail and assert that carried user spending rolls back while actual sender-paid fees remain charged.

Baseline state:

- T12, Amsterdam/EIP-8037 disabled, ordinary T7 storage-credit rules enabled for user execution.
- Existing sender nonce 1; native commitments already present. Fresh account/commitment setup is measured separately.
- Sender and sponsor have funded pathUSD balances; the recipient already holds one raw unit, so its balance slot is not first-created by the measured transfer.
- One transfer of 10 raw pathUSD units per main-matrix phase. Lifetime/periodic caps are 1,000,000,000 raw units. The two-cap policy authorizes two TIP-20 tokens and two unrestricted targets; only pathUSD is spent.
- The sponsor is a distinct primitive secp256k1 account. Sender-paid fees debit the same signed token budget as user transfers; sponsored fees do not.
- Carried fee reservation pays actual counter creation, including the T7 245,000-gas creditable component even though fee bookkeeping cannot consume/mint storage credits. User writes retain ordinary credits. A proposed 10,000-gas fee-settlement surcharge covers refund/activation/final-log work.
- `keychain_words_created` counts originally-zero, finally-nonzero keychain slots, not all touched slots or account configuration fields. Unlimited carried grants create no policy/counter words; limited grants create a counter only when that token is debited.
- Raw `gas` is receipt total gas. It is not a separate execution/state-gas decomposition. The draft requires that additional calibration before approval.

Environment: `rustc 1.100.0-nightly (a69a63265 2026-09-03)`, x86-64 AMD EPYC 4245P, container CPU quota 4 cores. The `execution_us` field is a single debug-build handler timing with concurrent build activity; it excludes fixture setup, local signing, wire conversion, networking, and durable disk writes. It is diagnostic only and must not be used for throughput or consensus-gas calibration.

## Reproduce

From this PR's head:

```sh
cargo test -p tempo-revm --lib carried_cost -- --ignored --nocapture --test-threads=1
cargo test -p tempo-primitives -p tempo-precompiles -p tempo-revm --lib
cargo test -p tempo-transaction-pool --lib
cargo test -p tempo-alloy -p tempo-node --lib carried
cargo +nightly fmt --all -- --check
cargo +nightly clippy -p tempo-primitives -p tempo-precompiles -p tempo-revm -p tempo-transaction-pool -p tempo-node --lib
```

Extract CSV lines by their emitted headers/prefixes; Rust harness/build lines are not data. Gas is deterministic for these fixtures; `execution_us` is not. An oversized stored policy row is explicitly marked rejected with no executed receipt; a zero in its gas column is not a zero-cost transaction.

Rechecked on 2026-09-11 at implementation commit
[`c7ed2924`](https://github.com/tempoxyz/tempo/commit/c7ed2924fc04642004f1aa1397985d3cd0ae8bdc):
all 1,784 CSV rows matched a fresh execution exactly after excluding `execution_us`
(1,782 executed receipts and two rejected stored setups). The three ignored cost tests
and all 13 focused `tempo-revm` carried-key tests passed. The plot generator checks matrix
coverage, duplicate scenario keys, rejection status, and both sides of each computed crossover.

## Review boundary

This is a draft reference implementation and measured fixture comparison. Independent security review, production-hardware worst-case calibration of the proposed constants, full-node/reorg/relay integration, richer trace metrics, explorer UI, client releases, and hardfork scheduling remain separate approval/rollout gates. Nothing here authorizes activation.
