# TIP-1172: T15 Hardfork Meta TIP

## Abstract

T15 disables the ValidatorConfig V1 precompile and the V1 to V2 migration
calls. This meta TIP links the individual TIPs and specifies the additional
protocol changes.

## Motivation

Collect the T15 upgrade scope and implementation links in one place for review.

---

# T15 TIPs

No individual TIPs are proposed behind T15 yet.

---

# Additional protocol changes

These changes are not covered by an individual T15 TIP. They are proposed behind
T15; pre-T15 execution rules are preserved.

## 1. Disable ValidatorConfig V1 and the V1 to V2 migration

**PR**: [#9350](https://github.com/tempoxyz/tempo/pull/9350) · **Author**: @SuperFluffy

From T15, every selector of the ValidatorConfig (V1) precompile reverts with
`UnknownFunctionSelector(bytes4)`, including its views. `migrateValidator` and
`initializeIfMigrated` on ValidatorConfigV2 ([TIP-1017](./tip-1017.md)) revert
the same way. All other ValidatorConfigV2 functions are unchanged.

Consensus, DKG and fee-recipient lookups read only ValidatorConfigV2 once it is
initialized, which it is on mainnet and Moderato. V1 writes therefore have no
effect, and the migration calls already revert there with `AlreadyInitialized`.
Before T15, V1 and the migration calls behave as before, so historical blocks
replay unchanged.

Tooling that still reads or writes V1, such as `xtask generate-add-peer`, must
use ValidatorConfigV2 on networks at T15 or later.
