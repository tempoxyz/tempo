# TIP-1102: Reprice Precompile and Opcode Gas Costs

## Abstract

This TIP removes the KZG point-evaluation precompile and updates the gas pricing
model for remaining EVM precompiles and opcodes whose measured execution
throughput is below 1 GGas/s on Tempo's benchmark suite. Repricing may adjust
either the underlying gas cost functions, the fixed gas values for specific
operations, or both, depending on how each cost is represented in the EVM
implementation.

The goal is to make gas accounting better reflect resource usage on Tempo while
preserving deterministic execution and compatibility with the fork activation
rules. The final specification will list each affected precompile and opcode,
its old cost, its new cost, its benchmarked throughput, and the rationale for
the repricing.

## Motivation

Some inherited EVM gas prices may not accurately represent Tempo's execution
environment, implementation costs, or desired block resource limits. If an
operation is underpriced, users can consume disproportionate CPU, memory,
database, or cryptographic verification resources relative to the gas charged.
If an operation is overpriced, useful contracts and protocol workflows may be
discouraged despite being inexpensive for Tempo nodes to execute.

Repricing selected precompiles and opcodes gives Tempo a clearer resource
market. It also creates an explicit place to document benchmark evidence,
compatibility impact, and the activation rules needed for node implementations,
tooling, and contract developers.

## Threat Model

If underpriced precompiles or opcodes are not repriced, an attacker can create a
gas-valid block whose execution cost prevents block builders or validators from
validating it in time, potentially denying service across the network.

# Point Evaluation Precompile Removal

At activation, the KZG point-evaluation precompile at
`0x000000000000000000000000000000000000000A` MUST be removed from the active
precompile set. Calls to this address MUST no longer perform KZG proof
verification and MUST follow ordinary EVM call semantics for the account at
that address. This removes the `point_evaluation` and
`point_evaluation_uncachable` benchmarks from the repricing requirement.

The existing 50,000 gas price is materially undervalued. If the precompile were
retained, its price would need to increase to 8,000,000 gas; this TIP removes it
instead.

# Security Considerations

This TIP only increases gas costs or removes the point-evaluation precompile; it
does not add functionality, expand the set of accepted inputs, or weaken
validation. No remaining operation becomes cheaper or can consume more
execution resources within the block gas limit, so the changes introduce no
additional protocol-level attack vector and reduce the denial-of-service risk
from underpriced execution.
