# TIP-1121: TIP-20 Additions Meta TIP

## Abstract

This TIP adds three features to TIP-20: independent pauses for transfers, mints, and burns; separate mint and burn roles; and `burnAt`. It also adds Zone portals to the set of addresses that `burnBlocked` and `burnAt` refuse to burn from.

All four changes activate at the same hardfork. This document specifies each change except `burnAt`, which extends [TIP-1006](./tip-1006.md).

## Motivation

Issuers moving tokens onto Tempo need to pause minting or burning without stopping transfers, assign mint and burn permissions separately, and burn tokens from other addresses.

## Assumptions

- Every TIP-20 role has an admin role. `DEFAULT_ADMIN_ROLE` is the zero hash. `UNGRANTABLE_ROLE` (`0xff…ff`) is self-administered and cannot be granted.
- The existing `paused` storage slot has only ever held `0` or `1`.
- Existing selectors keep their signatures. Behavioral changes are specified below and summarized in the migration rules.

# Specification

## 1. Granular pause

Today `pause()` blocks transfers, mints, and burns together. Issuers can now pause them independently.

### Interface

```solidity
/// @notice Bit flags naming the features that can be paused independently.
uint8 constant PAUSE_TRANSFER = 0x01;
uint8 constant PAUSE_MINT     = 0x02;
uint8 constant PAUSE_BURN     = 0x04;
uint8 constant PAUSE_ALL      = 0x07;

/// @notice Emitted whenever the paused feature set changes.
/// @param updater Caller that changed the state.
/// @param pausedFeatures Bitmask of features that are now paused.
event PauseFeaturesUpdate(address indexed updater, uint8 pausedFeatures);

/// @notice Bits set in features are added to the paused set. Requires PAUSE_ROLE.
function pause(uint8 features) external;

/// @notice Bits set in features are removed from the paused set. Requires UNPAUSE_ROLE.
function unpause(uint8 features) external;

/// @notice Returns the bitmask of currently paused features.
function pausedFeatures() external view returns (uint8);

error InvalidPauseFeatures();
```

### Behavior

`pause(features)` adds the selected features to the paused set. `unpause(features)` removes them. Both revert with `InvalidPauseFeatures` if `features` is zero or contains bits outside `PAUSE_ALL`.

The existing `pause()` and `unpause()` select `PAUSE_ALL` and keep their current role requirements. `paused()` returns `true` exactly when `PAUSE_TRANSFER` is set.

| Operation, including memo variants | Reverts with `ContractPaused` when |
|---|---|
| `transfer`, `transferFrom` | `PAUSE_TRANSFER` is set |
| Existing DEX pause checks, pre-transaction fee collection, ReceivePolicyGuard claims | `PAUSE_TRANSFER` is set |
| `mint` | `PAUSE_MINT` is set |
| `burn`, `burnBlocked`, `burnAt`, ReceivePolicyGuard's `burnBlockedReceipt` | `PAUSE_BURN` is set |

Receipt burns check `PAUSE_BURN`, not `PAUSE_TRANSFER`. Pausing transfers alone does not block them. Existing authorization and policy checks remain unchanged.

Post-transaction fee refunds remain allowed while paused, including when the transaction itself pauses the token.

Every change to the paused set emits `PauseFeaturesUpdate` with the new mask. A change to `paused()` also emits the existing `PauseStateUpdate(updater, isPaused)` event.

### Storage

At the fork, read the existing `paused` slot as follows:

| Stored value | Meaning |
|---|---|
| `0` | Nothing paused |
| `1` | Legacy full pause: all three features paused |
| `0x80 \| mask` | New encoding: `mask` is the paused feature bitmask |

After the fork, every write uses `0x80 | mask`, including `0x80` when nothing is paused. Never write the legacy value `1`. Treat any value outside these encodings as `PAUSE_ALL`.

## 2. Mint and burn role split

### Interface

```solidity
bytes32 public constant MINT_ROLE = keccak256("MINT_ROLE");
bytes32 public constant BURN_ROLE = keccak256("BURN_ROLE");

function MINT_ROLE() external view returns (bytes32);
function BURN_ROLE() external view returns (bytes32);
```

Both roles use `DEFAULT_ADMIN_ROLE` as their default admin.

### Behavior

| Operation | Required role: either of |
|---|---|
| `mint`, `mintWithMemo` | `ISSUER_ROLE`, `MINT_ROLE` |
| `burn`, `burnWithMemo` | `ISSUER_ROLE`, `BURN_ROLE` |

All other checks still apply. `burnBlocked` and `burnAt` keep their separate role requirements.

`ISSUER_ROLE` continues to authorize both minting and burning. To enforce separate permissions on a token:

1. Revoke `ISSUER_ROLE` from every holder.
2. Call `setRoleAdmin(ISSUER_ROLE, UNGRANTABLE_ROLE)` to prevent future grants.

Existing `ISSUER_ROLE` holders keep both powers at the fork. No storage changes.

## 3. `burnAt`

Activate `burnAt` and `BURN_AT_ROLE` from [TIP-1006](./tip-1006.md) at the same fork, with two additional rules:

- `burnAt` honors `PAUSE_BURN`.
- `burnAt` uses the same protected-address set as `burnBlocked` at activation, rather than TIP-1006's original list. This includes ReceivePolicyGuard from [TIP-1028](./tip-1028.md) and Zone portals from section 4.

## 4. Protect Zone portals from `burnBlocked` and `burnAt`

### Background

`burnBlocked` refuses to burn from a set of protected addresses. Each holds tokens that back claims owned by others: the fee manager and stablecoin DEX (genesis), the channel reserve (T5), and ReceivePolicyGuard (T6).

Zone portals hold tokens the same way and are missing from the set. A portal escrows every TIP-20 deposited into its Zone at its own address, and the Zone mints a matching mirror balance to the depositor. The mirror supply always equals the escrow. Burning the escrow leaves every Zone holder unbacked.

| Call | Precondition today |
|---|---|
| `burnBlocked(portal, amount)` | The token's transfer policy blocks the portal |
| `burnAt(portal, amount)` | Caller holds `BURN_AT_ROLE`; no policy check |

### Specification

- Every Zone portal address joins the protected set at activation. The Zone factory ([TIP-1096](./tip-1096.md)) deploys portals under the 12-byte prefix `0x5AD0000000000000000000` and exposes `isZonePortal(address)`. The protected check is a prefix match, with no registry lookup.
- `burnBlocked` and `burnAt` revert with the existing `ProtectedAddress` error when `from` is a Zone portal.
- The protected set is defined once and shared by both functions. Later additions apply to both.

### Scope

The protected set covers protocol-installed custody only: addresses the protocol itself deploys to hold tokens for others. Earn vaults, bridges, and third-party escrow contracts are not covered. A TIP that introduces new protocol custody must add its address to the set.

This does not add a compliance path into Zones. A Zone user blacklisted on Tempo is frozen inside the Zone, because Zones mirror TIP-403 policy state, but their balance cannot be burned or seized from Tempo. That needs an issuer-authorized action at the Zone level and belongs in the Zones specification.

# Migration rules

Existing selectors keep their signatures. Pause behavior follows section 1, mint and burn calls accept the additional roles in section 2, and `burnBlocked` gains the Zone portal protection in section 4. Role administration, grants, revocations, and renunciation otherwise remain unchanged for all tokens.

The pause slot uses the encoding in section 1. No migration scans existing state. All tokens upgrade in place because they are precompile-backed; no redeployment is required.
