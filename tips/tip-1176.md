# TIP-1176: Extended Access List Transactions

## Abstract

This TIP adds Tempo transaction type `0x77`: a type `0x76` transaction plus a
`flags` field and an extended access list that declares the accounts, storage
slots, and bytecode it will read or write. Declared resources pay
[TIP-1174](./tip-1174.md)'s declared price once, at declaration, and every
access then costs 100. Unlike EIP-2930 lists, the extended list distinguishes
reads from writes, so writes can be declared and clients can prefetch the trie
paths of the write set before execution.

This is component 3 of the [TIP-1139](./tip-1139.md) state access program.

## Motivation

Under TIP-1174, legacy EIP-2930 lists can only declare reads, so every contract
write pays the undeclared price. Declaring writes fixes that and gives clients
two things in advance: the state the transaction reads, and the trie nodes they
must update to compute the state root. Transaction-level declarations also work
with multiple concurrent proposers, where a block-level access list is unknown
until the whole block has executed.

### Alternatives considered

- **Extend EIP-2930 lists on type `0x76`:** changes the meaning of signed
  fields of an existing type.
- **Block-level access lists:** not available to each proposer before execution.

## Assumptions and amended TIPs

- [TIP-1174](./tip-1174.md) is active in the same or an earlier hardfork; this
  TIP uses its prices, warmth model, and refund columns.
- [TIP-1175](./tip-1175.md) defines `code_hash`. Until it is active,
  `code_hash` MUST be empty.
- [TIP-1177](./tip-1177.md) defines `flags` bit 0. Until it is active,
  `flags` MUST be zero.
- At activation this TIP amends [TIP-1045](./tip-1045.md): the payment
  classifier is extended to type `0x77` and still requires an empty list.

# Specification

## 1. Transaction format

Type `0x77` is a new EIP-2718 transaction type; its fee payer signs with prefix
`0x79`. Type `0x76` and its `0x78` fee-payer domain are unchanged.

```text
0x77 || rlp([
    chain_id, max_priority_fee_per_gas, max_fee_per_gas, gas_limit,
    calls, nonce_key, nonce, valid_before, valid_after, fee_token,
    fee_payer_signature, tempo_authorization_list, key_authorization,
    flags, extended_access_list, sender_signature
])
```

All 16 fields are required. Shared fields keep their type `0x76` meaning from
[TIP-0001](./tip-0001.md) and its active amendments. An absent
`key_authorization` is the empty RLP string. `calls` is non-empty. There is
no EIP-2930 `access_list` field.

`flags` is a canonical RLP integer. All bits not defined by an active TIP MUST
be zero. Invalid lengths, extra fields, non-canonical RLP, unknown flags, or
malformed declarations make the transaction invalid.

### Extended access list

```text
extended_access_list = [account_entry, ...]
account_entry = [address, account_flags, code_hash, read_keys, write_keys]
read_keys = [key, ...]
write_keys = [key, ...]
```

- `address` is 20 bytes; `key` is 32 bytes.
- `account_flags` is a canonical RLP integer: bit 0 declares an account read
  and bit 1 an account write. Bit 1 requires bit 0, so the valid values are 0,
  1 (read), and 3 (read/write).
- `code_hash` is the empty string or, under TIP-1175, a 32-byte code hash.
- `read_keys` declares storage reads and `write_keys` storage writes for the
  account. A key MUST NOT appear in both lists.
- Account entries are strictly ordered by address bytes, and each key list by
  key bytes. Duplicates are invalid, as is an entry with `account_flags == 0`,
  an empty `code_hash`, and both key lists empty.
- At most 512 account entries. The list's RLP encoding is at most 65,536 bytes
  and the signed transaction at most 131,072 bytes.

An account declaration covers nonce, balance, existence, and code hash. Storage
keys cover slots of the account whose storage is executing (the `ADDRESS` of the
frame). Empty and nonexistent accounts can be declared. Write permission
includes read. The list applies unchanged to all calls and frames. Transient
storage, memory, calldata, and block environment need no declaration.

### Hashes and signatures

Let `U` be the first 15 fields (all but `sender_signature`).

- **Sender hash:** `keccak256(0x77 || rlp(sender_U))`. If the transaction is
  sponsored (`fee_payer_signature` non-empty), `sender_U` replaces
  `fee_payer_signature` with the byte `0x00` and `fee_token` with the empty
  string; otherwise it replaces `fee_payer_signature` with the empty string.
- **Fee payer hash:** `keccak256(0x79 || rlp(fee_payer_U))`, where
  `fee_payer_U` keeps the actual `fee_token` and replaces
  `fee_payer_signature` with the 20-byte sender address.
- **Transaction hash:** `keccak256(signed_wire_bytes)`.

Both signing hashes cover every field, including `flags` and the full list.
Signature formats, key authorization, and recovery follow the active Tempo rules.
The expiring-nonce replay identity is
`keccak256(0x77 || rlp(sender_U) || sender_address)`. Receipts use type `0x77`
with the type `0x76` payload.

## 2. Lane classification

A type `0x77` transaction is classified by the active TIP-1045 classifier, with
the extended list in place of `access_list`: a payment transaction must have an
empty list. Everything else is general, unless [TIP-1177](./tip-1177.md) places
it in the access list lane.

## 3. Declaration charges

A type `0x77` transaction pays, in intrinsic execution gas:

```text
16 * len(rlp(extended_access_list))
+ 100
+ 2_000 * count(entries with account_flags == 1)
+ 4_900 * count(entries with account_flags == 3)
+ 3_000 * count(entries with a non-empty code_hash)   (TIP-1175)
+ 2_000 * count(read_keys)
+ 4_900 * count(write_keys)
```

The 100 covers validation, and each list byte costs 16 gas. List bytes do not
count as calldata for TIP-1016's calldata floor. Unused declarations are not
refunded. An empty list costs 116 gas; one account-read entry (27 bytes) costs
`16 * 27 + 100 + 2_000 = 2_532`.

Declarations make their resources warm from the start of execution: the account
bits make the account read-warm and write-warm, a read key makes its slot
read-warm, and a write key makes its slot read- and write-warm. A slot written
under a write key is refunded from TIP-1174's declared column; all other
accesses follow TIP-1174.

## 4. Prefetching state and the write set

Clients MUST validate bounds, ordering, signatures, fee authorization, and
intrinsic gas before prefetching. Clients SHOULD prefetch:

- every declared account, storage slot, and (under TIP-1175) code hash;
- the storage-credit counter of every account with declared write keys;
- the account and storage trie paths of every declared write, so state root
  computation can start before execution ends.

Never fetch all storage of an address or follow unlisted code. Prefetch is local
and never affects gas. A client that executes transactions speculatively in
parallel MUST detect conflicts and reproduce the serial result, since an
undeclared access can conflict with another transaction.

## 5. Activation

At activation type `0x77` becomes valid and the transaction pool is
revalidated. Earlier blocks replay under their own rules. An incomplete list can
cost more after another transaction changes state that a contract branches on;
clients should regenerate it when resubmitting.

# Gas Cost Impact

General lane, declaration charges included, list bytes (about 530 gas per key)
excluded:

| Storage sequence | Baseline | Undeclared (TIP-1174) | Declared |
| --- | ---: | ---: | ---: |
| Cold SLOAD | 2,100 | 4,000 | 2,100 |
| Cold read then write (ERC-20 balance update) | 5,000 | 14,000 | 5,100 |
| Cold write then restore, no read, net | 2,300 | 4,100 | 2,200 |
| Cold read, write, restore (reentrancy guard), net | 2,300 | 8,100 | 2,300 |

# Tooling

SDKs and signing libraries MUST support type `0x77`, its list, flags, and both
signature domains. JSON transaction objects expose `type: "0x77"`, `flags`, and
`extendedAccessList`: an array of `{address, accountFlags, codeHash, readKeys,
writeKeys}`, with `flags` and `accountFlags` as hex quantities, `codeHash` as
a 32-byte hex string or `null`, and keys as 32-byte hex strings.

`tempo_createExtendedAccessList(transaction, blockSelector)` simulates the
transaction without committing and returns `extendedAccessList`, `gasUsed`,
`executionGasUsed`, `stateBlockHash`, and `serialAccesses`:

- The block selector is a number, hash, `latest`, `safe`, or `finalized`;
  `pending` is rejected with `-32602`.
- It collects every attempted access, including on reverted paths; written slots
  go in `writeKeys` and written accounts get the write bit. Prewarmed addresses
  and storage-credit counters are not collected.
- For a payment-eligible transaction it returns an empty list and the gas under
  inference.
- It re-simulates with the generated list and reports remaining misses in
  `serialAccesses` as `{address, kind, access, key?}`. Results are canonical;
  overflowing list or transaction bounds returns `-32602`.

`eth_estimateGas` uses the submitted declarations. `eth_createAccessList`
remains EIP-2930.

# Observability

Clients MUST emit per-transaction declaration gas and undeclared-access counts.
Traces MUST give each undeclared access's resource, required and declared
permission, charged gas, and frame depth. Clients SHOULD measure prefetch queue
depth, bytes, latency, and failures.

# Threat Model

Senders and sponsors can omit resources, understate write permissions, or pad
declarations; undeclared prices, upfront declaration charges, bounds, and
signatures (which bind the sender or sponsor to the list it paid for) limit this.

# Invariants and Validation

1. Signing hashes bind `flags` and every declaration; `0x76` and `0x77`
   domains never collide.
2. Malformed or oversized lists are invalid; incomplete lists are valid.
   Payment transactions have empty lists.
3. Each declared permission is paid for once, upfront.

Reference tests MUST cover encoding and signature fixtures for sponsored and
unsponsored transactions, exact list, byte, and gas bounds, every declaration
kind, read-only declarations followed by writes, write-key refunds, rejection of
non-empty payment lists, and activation.
