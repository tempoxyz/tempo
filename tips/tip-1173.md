# TIP-1173: Out-of-State Expiring Nonce Set

## Abstract

This TIP removes expiring nonce replay protection from the Nonce precompile's storage. Nodes keep the set of unexpired replay hashes outside EVM state, bucketed by `validBefore`, and a new header field, `expiringNonceRoot`, commits to it. A bucket is dropped whole when its second passes, so the ring, its pointer, its fixed capacity and `ExpiringNonceSetFull` go away. Expiring nonce transactions no longer write shared state, and zone provers verify replay protection from a small per-transaction witness. The main limitation: every node must keep the set in memory and rebuild it from the last `MAX_EXPIRY_SECS` of blocks after a restart.

## Motivation

TIP-1009 stores replay protection in EVM state: `expiringNonceSeen[hash]`, a 3,000,000-entry ring and a ring pointer ([TIP-1093](./tip-1093.md)). This has three costs.

1. **Shared writes.** Every expiring nonce transaction reads and writes `expiringNonceRingPtr` and an eviction slot, so any two expiring nonce transactions in a block conflict under optimistic parallel execution. [TIP-1170](./tip-1170.md) removes the pointer conflict, but each transaction still does 2 cold reads and 3 writes in the state trie, and the block pays to rehash those slots in the state root.
2. **Fixed capacity.** The ring holds 10,000 TPS × 300 s of entries. Beyond that rate inserts fail with `ExpiringNonceSetFull`, which caps expiring nonce throughput below the chain's target. Raising the capacity or the window grows state by about 107 bytes per entry (321 MB at today's capacity, [TIP-1093](./tip-1093.md#replay-protection-capacity)).
3. **Zone witnesses.** A zone batch proof carries a state witness for every Nonce precompile slot its transactions touch, including the ring slot and the evicted entry's slot. These are scattered across a 3,000,000-entry mapping, so their paths rarely share nodes.

None of this needs to be state. A replay hash commits to its transaction's `validBefore` (TIP-1009, [TIP-1106](./tip-1106.md)), so a replay always carries the original's `validBefore`. Grouping entries by `validBefore` means a lookup touches one group and a whole group expires at once when the block timestamp reaches it: no ring, no pointer, no per-entry eviction.

### Alternatives considered

- **Keep the ring, index it by block position ([TIP-1170](./tip-1170.md)).** Removes the pointer conflict with no data-structure change. It keeps the state footprint, the capacity limit and the zone witness cost. It is a reasonable step before this TIP and becomes unnecessary once this TIP activates.
- **Bucket by `validBefore` inside EVM storage.** EVM storage cannot drop a mapping. Clearing a bucket costs one SSTORE per entry, paid either by transactions (which reintroduces a shared cursor) or by a block-end sweep of unbounded cost.
- **Rebuild the set from recent blocks with no header commitment.** Works for full nodes, but a stateless verifier (a zone prover or light client) would need every expiring nonce hash of the last `MAX_EXPIRY_SECS` in each witness: about 300 s × TPS × 32 bytes per batch, growing with throughput.
- **Balanced binary trees (AVL, red-black).** Shape depends on insertion order, rebalancing rehashes nodes off the insert path, and absence proofs need both neighbours. A trie keyed by uniform hashes stays balanced in expectation and has one root per set regardless of order.
- **Merkle mountain range or append-only log.** Cannot prove absence.
- **Sorted-array Merkle tree.** Every insert shifts later indices.
- **RSA or KZG accumulators, Verkle.** Too slow and complex for this use.

## Assumptions

- **A1. A replay hash determines its `validBefore`.** The replay hash (`unique_tx_identifier` since T1B) covers the signed transaction, including `validBefore`. If a future transaction format let one replay hash carry different `validBefore` values, a replay could land in a different bucket and go undetected.
- **A2. Every included expiring nonce transaction inserts its hash.** As in TIP-1009, the replay check runs during nonce validation. A transaction that fails it is invalid, and so is any block containing it. An included transaction's hash is inserted even if its calls revert.
- **A3. Nodes can read the last `MAX_EXPIRY_SECS` of canonical block bodies.** Nodes rebuild the set from them on restart ([Persistence and recovery](#persistence-and-recovery)). A node pruned or synced without them cannot rebuild the set itself and must get it from a peer.
- **A4. Block timestamps do not decrease.** Expiry drops buckets with `validBefore <= timestamp`. Tempo consensus already rejects a block with a timestamp below its parent's.
- **A5. Nothing on-chain reads replay protection from state.** The Nonce precompile has no getter for `expiringNonceSeen` (`INonce` has only `getNonce`), and contracts cannot read another account's storage. Off-chain tools that read the slots with `eth_getStorageAt` stop seeing new entries after activation ([Compatibility](#compatibility)).

# Specification

## Overview

Terms:

- **Expiring nonce transaction**: a Tempo transaction (type `0x76`) with `nonceKey == uint256.max`, as in TIP-1009.
- **Entry**: the pair `(H, v)` of an expiring nonce transaction's replay hash `H` (TIP-1009, TIP-1106; `unique_tx_identifier` since T1B) and its `validBefore` `v`.
- **Bucket `v`**: the entries with `validBefore == v`.
- **Expiring nonce set `S(B)`**: the live entries after block `B`, those with `validBefore > timestamp(B)`.
- **`expiringNonceRoot`**: the commitment to `S(B)`, carried in `B`'s header.

Each block moves the set forward in four stages:

1. **Expire**: drop every bucket with `v <= timestamp(B)` from the parent's set.
2. **Check and insert, per transaction**: reject a transaction whose entry is already in the set, otherwise insert it. This replaces TIP-1009's ring algorithm and touches no EVM state.
3. **Commit**: after the last transaction, recompute the roots of the buckets the block touched, then `expiringNonceRoot`.
4. **Verify**: validators recompute the root from the parent's set and the body, and reject the block if it differs from the header.

The set is a pure function of the chain: the parent set, the block timestamp and the body. Nobody signs or chooses it. A proposer can affect it only by including or excluding transactions, as today.

Zones apply the same rules to their own chain. A zone block's header carries that zone's root, and the zone prover checks it from a witness against the parent zone header ([Zones](#zones)).

## Mechanics

### Commitment structure

Each bucket is a Merkle Patricia Trie (MPT), as in the Ethereum state trie, keyed by the raw 32-byte replay hash `H` (not hashed again). Every leaf holds the RLP value `0x01`. An empty bucket's root is `EMPTY_ROOT_HASH`, and an empty bucket is never stored.

The set trie is an MPT keyed by `v` as a 32-byte big-endian word (not hashed). Its values are the RLP encodings of the non-empty buckets' roots. `expiringNonceRoot` is its root, so an empty set has root `EMPTY_ROOT_HASH`.

Both tries use keccak-256, and a root depends only on the set's contents, not on insertion order. Keys are not hashed again: replay hashes are already uniform, and the set trie has at most `MAX_EXPIRY_SECS` keys.

A membership or absence proof is one path in the set trie plus one path in the bucket. At 10,000 entries per bucket (10,000 TPS sharing one `validBefore`), a bucket path is about 4 branch nodes. The set trie holds at most 300 keys, so its path is 2–3 nodes.

### Per-block transition

For block `B` with parent `P`, timestamp `t`, and its expiring nonce transactions in body order:

1. **Expire.** Start from `S(P)` and remove every bucket with `v <= t`.
2. **Per transaction**, for entry `(H, v)`, during nonce validation and in body order:
   1. **Expiry window.** Reject with `InvalidExpiringNonceExpiry` unless `t < v <= t + MAX_EXPIRY_SECS` (unchanged).
   2. **Replay check.** Reject with `ExpiringNonceReplay` if `H` is in bucket `v`, including entries inserted earlier in the same block.
   3. **Insert.** Add `H` to bucket `v`.
3. **Commit.** After the block's last transaction, including end-of-block system transactions, recompute the root of each bucket the block inserted into, then the set root, and write it to the header's `expiringNonceRoot`.

A rejection in step 2 makes the transaction invalid, as under TIP-1009, and any block containing it is invalid. Builders skip such candidates. Step 2 reads and writes no EVM storage, so it produces no state change, block access list entry, log or trace record. It replaces the Nonce precompile's `checkAndMarkExpiringNonce` logic.

There is no capacity check. Bucket size is bounded only by block gas, and `ExpiringNonceSetFull` cannot occur.

### Block validation

A validator executing `B` derives `S(B)` from `S(P)` as above and rejects `B` if:

- the header lacks `expiringNonceRoot` at or after activation, or carries one before it; or
- `expiringNonceRoot` differs from the root of `S(B)`.

The root is checked alongside the state root, after execution.

### Gas

`EXPIRING_NONCE_GAS` becomes 3,000 (proposed). TIP-1009's 13,000 paid for 2 cold reads, 1 warm read and 3 writes in the state trie. The new charge covers an in-memory lookup and insert, plus the transaction's share of rehashing one bucket path and the set trie at commit. It does not depend on bucket size, position or the rest of the block. Expiring nonce transactions create no persistent state and pay no [TIP-1016](./tip-1016.md) state gas, as before. The final value should come from benchmarks of the commit step at target throughput ([Open questions](#open-questions)).

### Activation

The TIP activates at a network upgrade (TBD). Let `F` be the first block at or after the activation timestamp.

- **Initial set.** `S(parent(F))` is every entry `(H, v)` of an expiring nonce transaction included before `F` with `v > timestamp(parent(F))`. All of them are in the last `MAX_EXPIRY_SECS` of blocks before `F`. Nodes SHOULD build this set in shadow mode before activation so they reach `F` with it in memory.
- **Block `F`** applies the per-block transition to that set and carries the first `expiringNonceRoot`.
- **Old storage.** From `F`, nothing reads or writes Nonce precompile slots 1 (`expiringNonceSeen`), 2 (`expiringNonceRing`) or 3 (`expiringNonceRingPtr`). Their values stay in state, frozen. Every live entry among them is in the initial set, so no replay window opens. This TIP does not clear them ([Open questions](#open-questions)).

[TIP-1170](./tip-1170.md), if active, stops applying at `F` because the ring is no longer written.

### Persistence and recovery

The set is not in the state trie, so nodes keep it themselves.

- **Snapshots by block.** A node keeps `S(B)` for every block it may build on, including notarized blocks not yet finalized. Snapshots share buckets and copy on write.
- **Restart.** A node rebuilds `S(head)` from an empty set by applying every canonical block with timestamp greater than `timestamp(head) - MAX_EXPIRY_SECS`. The result MUST match the head header's `expiringNonceRoot`. A live entry (`v > timestamp(head)`) was included in a block with timestamp at least `v - MAX_EXPIRY_SECS`, so this replay sees every live entry.
- **Sync.** A node syncing state from a snapshot needs the last `MAX_EXPIRY_SECS` of block bodies before its starting head, or the set from a peer, checked against the header root.

Memory tracks live entries, not history: up to 3,000,000 hashes at 10,000 TPS with a 300 s window, and 15,000,000 at 50,000 TPS, each a 32-byte key plus trie node overhead.

### Transaction pool

The pool checks a candidate against the set at the canonical head instead of reading `expiringNonceSeen[H]`, and removes mined transactions using each new block's inserted entries instead of watching writes to the seen slot. The expiry window check is unchanged.

### Zones

Each zone keeps its own set under the same rules. Zone block headers carry the zone's `expiringNonceRoot`, and the zone sequencer maintains the set as a full node does.

The zone prover (`zone_spf`) verifies the transition statelessly:

1. `BatchWitness` gains `expiringNonceWitness`: a deduplicated pool of RLP-encoded trie nodes from the batch's parent set (set trie and bucket tries), covering the path of every entry the batch checks.
2. The prover reads `expiringNonceRoot` from the parent zone header, which the witness already authenticates by hash.
3. For each zone block, it applies the per-block transition on the revealed tries: drop expired buckets from the set trie, prove absence and insert each entry, and recompute the root. A transaction whose path the witness does not reveal fails the proof.
4. It writes the root into each assembled zone header. Each header hash feeds `block_transition`, which binds the root to the batch output.

Later blocks in a batch build on the tries as earlier blocks left them. The witness covers only paths in the parent set, so it grows with the batch's expiring nonce transactions and not with the window or throughput. The Nonce precompile's expiring nonce slots leave `zoneStateWitness`.

## Interfaces

### Header

`TempoHeader` gains a trailing optional field:

```rust
pub struct TempoHeader {
    pub general_gas_limit: u64,
    pub shared_gas_limit: u64,
    pub timestamp_millis_part: u64,
    pub inner: Header,
    pub consensus_context: Option<TempoConsensusContext>,
    /// Root of the expiring nonce set after this block (TIP-1173). None before activation.
    pub expiring_nonce_root: Option<B256>,
}
```

RLP: `[general_gas_limit, shared_gas_limit, timestamp_millis_part, inner, consensus_context?, expiring_nonce_root?]`. The encoding is `trailing(no_gaps)` today and zone headers have no `consensus_context`, so a header with `expiring_nonce_root` but no `consensus_context` encodes `consensus_context` as the empty string `0x80`. Decoders accept `0x80` there only when `expiring_nonce_root` follows. JSON: `expiringNonceRoot`, omitted when `None`.

### Nonce precompile

No ABI, selector or event changes. From activation:

```solidity
contract Nonce {
    mapping(address => mapping(uint256 => uint64)) public nonces; // slot 0: unchanged
    mapping(bytes32 => uint64) public expiringNonceSeen;          // slot 1: frozen
    mapping(uint32 => bytes32) public expiringNonceRing;          // slot 2: frozen
    uint32 public expiringNonceRingPtr;                           // slot 3: frozen
}
```

Errors, raised as transaction-invalid during nonce validation:

```solidity
/// @notice validBefore is not in (now, now + MAX_EXPIRY_SECS].
error InvalidExpiringNonceExpiry();
/// @notice The replay hash is already in its validBefore bucket of the expiring nonce set.
error ExpiringNonceReplay();
```

`ExpiringNonceSetFull` is no longer raised from activation.

### Zone witness

```rust
pub struct BatchWitness {
    // ...existing fields...
    /// Deduplicated RLP-encoded nodes of the parent expiring nonce set's set and bucket tries,
    /// covering every entry the batch checks (TIP-1173).
    pub expiring_nonce_witness: Vec<Bytes>,
}
```

### RPC

Nodes MAY expose `tempo_getExpiringNonceProof(hash, validBefore, block)`, returning the set-trie and bucket-trie proof nodes for the entry against `expiringNonceRoot` at `block`, and whether it is present.

# Compatibility

| Integration | What changes |
|---|---|
| Block header (RLP, JSON, hash) | New trailing `expiring_nonce_root`. Decoders, explorers and indexers must accept it. Block hashes from activation commit to it. |
| Node execution (`crates/evm`, `crates/precompiles/src/nonce`) | The check moves from the Nonce precompile to the executor's set. `EXPIRING_NONCE_GAS` changes. The executor computes the root; validation compares it. |
| Payload builder, prewarming, action replay | Check against the parent's set plus the block's own entries. `expiring_nonce_idx` and the ring pointer save/restore are no longer needed. |
| Node persistence and startup | Per-block set snapshots; rebuild from the last `MAX_EXPIRY_SECS` of blocks. Pruning must keep those bodies. |
| Transaction pool (`crates/transaction-pool`) | Replay pre-check uses the head set, not the `expiringNonceSeen` slot. Mined-transaction tracking uses block entries, not slot writes. |
| Zones (`crates/zones/spf`, sequencer, zone node) | Zone headers carry the root. `BatchWitness` gains `expiring_nonce_witness`. The witness builder collects set paths instead of Nonce precompile storage paths. |
| `eth_getStorageAt` on Nonce slots 1–3 | Returns frozen pre-activation values. Replay-status checks must use the node's set or `tempo_getExpiringNonceProof`. |
| Tracers, block access lists | Expiring nonce transactions no longer show Nonce precompile reads or writes. |
| SDKs, wallets, transaction format | Unchanged: `nonceKey`, `nonce`, `validBefore` and the replay hash are the same. |
| `crates/state-bloat`, test helpers | Fixtures that fill or inspect the ring need set-based equivalents. |

The window stays `MAX_EXPIRY_SECS = 300`. Out of state, a longer window costs only node memory, like higher throughput, and does not grow the zone witness, so a later TIP can raise it without a storage migration.

# Observability

No events are added. Nodes SHOULD report:

- live entries and buckets after each block, to size memory;
- root recompute time per block, which bounds block time;
- root mismatches against received headers, which indicate a consensus bug or corrupt set;
- rebuild time and source (local bodies or peer) at startup.

Before activation, nodes running the set in shadow mode SHOULD count every disagreement with the ring in either direction. Activation should wait until testnet shows none.

# Threat Model

**A node computes the wrong set.** The most consequential failure: a node that drops a bucket early or late, misses entries after a restart, or uses a trie implementation that hashes differently computes a different root and rejects valid blocks or builds invalid ones. The per-block root comparison catches it at once, and the startup rebuild must match the head header before the node participates.

**Replay through faulty expiry.** A node that dropped a live bucket would accept a replay its peers reject. That block fails validation on honest nodes, so one faulty node cannot cause a replay. A1 and A4 guarantee a live replay always finds its original in the same bucket.

**Set-filling DoS.** With no fixed capacity, filling the set costs gas per entry, and live entries are bounded by `MAX_EXPIRY_SECS` times the gas-limited expiring nonce rate. Insertion can no longer fail, so the TIP-1009 attack of filling the ring to block other users' expiring nonce transactions goes away.

**Bucket concentration.** Most transactions use `validBefore = now + window`, so one bucket may hold most of a second's entries. Keys are uniform hashes, so a large bucket is still a balanced trie with logarithmic paths. Unbalancing it would require choosing replay hashes, which keccak-256 prevents.

**Zone prover.** The prover supplies `expiring_nonce_witness`, and the parent zone header's hash authenticates its root. Omitting a path fails the proof, and an absence cannot be faked because revealed nodes must hash to the committed root.

| Actor | Controls | Trusted to | Enforcing check | If wrong |
|---|---|---|---|---|
| Proposer/builder | Body, inclusion, `expiringNonceRoot` | Nothing | Validators recompute the set and compare the root | Block rejected |
| Transaction sender | `H`, `validBefore` | Nothing | Window and replay checks | Transaction invalid |
| Node operator | Pruning, restarts, sync source | Keep `MAX_EXPIRY_SECS` of bodies or fetch the set | Rebuilt root must match the head header | Node cannot follow the chain |
| Zone prover | `expiring_nonce_witness` | Nothing | Revealed nodes hash to the parent zone header's root | Proof fails |

Residual risks: a node that loses both its set and recent bodies needs a peer to recover, and memory grows with sustained throughput. Excluded: other shared state expiring nonce transactions write, such as fee accounting.

# Invariants

- **I1. No replay.** No replay hash executes twice while its `validBefore` is greater than the block timestamp (TIP-1009 E1).
- **I2. Exact contents.** After every block `B`, `S(B)` equals the set of entries of expiring nonce transactions included in canonical blocks up to `B` with `validBefore > timestamp(B)`.
- **I3. Canonical root.** `B`'s `expiringNonceRoot` equals the root of `S(B)` under the commitment structure, independent of insertion order and node storage.
- **I4. No state access.** From activation, no transaction or block reads or writes Nonce precompile slots 1–3.
- **I5. No capacity failure.** From activation, no valid expiring nonce transaction is rejected for lack of space.
- **I6. Fixed gas.** An expiring nonce transaction's intrinsic gas does not depend on bucket size, set size or its position in the block.
- **I7. Rebuild equivalence.** A set rebuilt from the last `MAX_EXPIRY_SECS` of blocks equals the set of a node that never restarted.
- **I8. Zone equivalence.** For every block in a zone batch, the prover's root equals the sequencer's.

## Test cases

1. **Differential with the ring.** Before activation, randomized blocks give the same accept/reject result per expiring nonce transaction under TIP-1009 and under the shadow set.
2. **Replay.** A second inclusion in the same or a later block fails `ExpiringNonceReplay`, and a block containing it is invalid.
3. **Expiry boundary.** Bucket `v` is dropped at block timestamp `v`. The same transaction cannot be resubmitted then, since `v <= t` fails the window check; one re-signed with a new `v` has a new `H` and is accepted.
4. **Order independence.** The same entries inserted in different orders give the same root.
5. **Activation.** Live entries from the last `MAX_EXPIRY_SECS` before `F` are in the initial set, and replaying any of them at or after `F` fails. Slots 1–3 are unchanged from `F`.
6. **Restart.** Stop a node at random heights and rebuild: the root matches the head header and later blocks validate.
7. **High load.** Sustain more than 10,000 expiring nonce TPS for over 300 s with no `ExpiringNonceSetFull` and memory bounded by the live window.
8. **Header encoding.** Round-trip headers with and without `consensus_context` and `expiring_nonce_root`, including the `0x80` placeholder, and reject a placeholder with no root after it.
9. **Zone proof.** A batch with expiring nonce transactions across several blocks proves with the minimal witness and fails if any needed node is removed.
10. **Reverted calls.** An expiring nonce transaction whose call reverts still inserts its entry.

# Open Questions

1. **Gas.** Benchmark the commit step (bucket path and set-trie rehash) at 50,000 TPS and set `EXPIRING_NONCE_GAS` from it; 3,000 is a placeholder.
2. **Trie shape.** A hexary MPT reuses reth's sparse trie and the zone prover's MPT code. A binary sparse trie (Jellyfish-style) cuts a bucket absence proof to about 14 hashes (about 450 bytes) at 10,000 entries but needs new code on both sides. Is the smaller zone witness worth it?
3. **Frozen storage.** Should a later fork clear Nonce slots 1–3 (about 321 MB at a full ring) or leave them?
4. **Header placeholder.** Is a `0x80` placeholder for an absent `consensus_context` acceptable, or should zone headers use a separate trailing layout?
5. **Sync.** Should peers serve the set at a finalized block over p2p, so snapshot-synced nodes need no recent bodies?
