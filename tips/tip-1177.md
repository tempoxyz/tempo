# TIP-1177: Access List Lane

## Abstract

This TIP defines `flags` bit 0 of [TIP-1176](./tip-1176.md) transactions as
`access_list_lane`. Flagged transactions go into a new lane of 100 million
execution gas per block, where undeclared first accesses cost 10× the declared
price. The general lane and the per-transaction execution cap shrink from 30
million to 16,777,216 (2^24, matching EIP-7825).

This is component 4 of the [TIP-1139](./tip-1139.md) state access program.

## Motivation

Declared execution can be prefetched, so a block can hold far more of it than of
execution that discovers state as it goes. A separate lane about six times the
general lane's size gives applications that declare their state the throughput,
while a smaller general lane bounds the worst-case serial work per block. An
undeclared lookup stalls a lane sized for prefetched execution, so misses there
are expensive.

### Alternatives considered

- **Raise the general lane only:** adds capacity without rewarding advance
  knowledge of state dependencies.
- **Reject transactions with incomplete lists:** makes inclusion depend on
  simulation accuracy; undeclared prices bound the cost of a miss instead.

## Assumptions and amended TIPs

- [TIP-1174](./tip-1174.md) and [TIP-1176](./tip-1176.md) are active in the
  same or an earlier hardfork. [TIP-1175](./tip-1175.md) is independent.
- Block builders pack transactions across lanes, and wallets can generate
  extended access lists, before this lane is useful.
- At activation this TIP amends:
  - [TIP-1010](./tip-1010.md): adds the access list lane; general gas limit and
    transaction gas cap from 30,000,000 to 16,777,216; shared (subblock) gas
    limit to zero, as subblocks are disabled since [TIP-1046](./tip-1046.md).
    The guaranteed payment capacity becomes 383,222,784, replacing TIP-1010's
    10,000-transfer capacity invariant.
  - TIP-1016: `max_transaction_gas_limit` to 16,777,216.

# Specification

## 1. Lane classification

Classify each transaction once, before execution:

1. A type `0x77` transaction with `flags & 1 == 1` is an **access list**
   transaction.
2. Otherwise, the active TIP-1045 classifier decides **payment** eligibility.
3. Everything else is **general**.

Legacy EIP-2930 lists cannot select the access list lane. The flag is the
sender's claim that its list covers execution, not a validity requirement: a
flagged transaction with an empty or incomplete list stays in the access list
lane and pays undeclared prices for what it missed. Builders MAY decline such
transactions; validators MUST NOT reject them for incomplete coverage.

## 2. Lane limits

| Parameter | Execution gas |
| --- | ---: |
| Total block limit | 500,000,000 |
| General lane limit | 16,777,216 |
| Access list lane limit | 100,000,000 |
| Per-transaction execution cap, all lanes | 16,777,216 |

With `g(tx)` the TIP-1016 execution-gas block contribution, a valid block
satisfies:

```text
sum(g(tx) for all transactions)          <= 500_000_000
sum(g(tx) for general transactions)      <= 16_777_216
sum(g(tx) for access list transactions)  <= 100_000_000
```

Payment transactions count only against the total, so they get at least
383,222,784 when both other lanes are full (about 7,660 transfers at 50,000 gas,
instead of 10,000). Unused capacity in one lane does not raise another's cap. A
signed `gas_limit` may exceed the per-transaction cap only to pay state gas.

## 3. Access list lane prices

The access list lane adds a column to TIP-1174 section 2:

| Access | Declared | Access list lane, undeclared |
| --- | ---: | ---: |
| Account or storage read | 2,000 | 20,000 |
| Account or storage write | 4,900 | 50,000 |
| Code component | 3,000 | 30,000 |
| Bytecode load (account read + code) | 5,000 | 50,000 |
| Any warm access | 100 | 100 |

Its refund components (TIP-1174 section 8) are 20,000 (access, never refunded)
and 30,000 (write, refundable). All other TIP-1174 and TIP-1176 rules apply
unchanged. For example, a transaction that declares a slot read-only pays 2,000
at declaration, 100 per SLOAD, 50,000 for its first SSTORE, and 100 per later
SSTORE; 30,000 is refunded if the slot ends at its original value.

## 4. Fees

All lanes use the active gas price and sponsorship rules, with no lane-specific
price. The [TIP-1067](./tip-1067.md) base fee controller uses total execution
gas across lanes, unchanged. Under sustained load in any lane the base fee rises
to its cap; beyond that, a full general lane clears through priority fees, which
rewards moving to the access list lane.

## 5. Activation

At activation the flag, lane limits, and prices take effect, and the transaction
pool is revalidated. Earlier blocks replay under their own rules. Maximum-size
deployments remain possible because state gas is outside the execution cap.

# Block Building

Builders fill each lane up to its limit and SHOULD order access list
transactions so that their prefetch overlaps execution. Builders SHOULD
deprioritize access list transactions whose simulated undeclared accesses are a
large share of their gas.

# Tooling

`tempo_createExtendedAccessList` defaults `flags` to `0x0` for a
payment-eligible transaction and `0x1` otherwise. Wallets SHOULD generate a list
and set the flag for contract interactions.

# Observability

Clients MUST emit per-block execution gas by lane and each transaction's lane.

# Threat Model

Proposers can misclassify or overfill lanes; validators recompute both. The
cheapest undeclared lookup is 4,000 gas in the general lane and 20,000 in the
access list lane, so a block holds at most about 9,200 undeclared lookups
(`16_777_216 / 4_000 + 100_000_000 / 20_000`), compared with about 14,300 cold
SLOADs in today's general lane. About 38,000 declared reads fit in the access
list lane; they are prefetchable but not free.

# Invariants and Validation

1. Each user transaction counts against exactly one lane and the total, in
   TIP-1016 execution gas; state gas never adds execution capacity.
2. A miss never changes a transaction's lane; legacy lists never select the
   access list lane.

Reference tests MUST cover lane classification, exact lane limits, the
transaction cap, access list lane prices and refunds, and activation.

Success criteria: most non-payment execution gas moves to the access list lane,
undeclared accesses there stay a small share of its gas, the general lane no
longer fills every block, and blocks with a full access list lane execute within
the block time budget.
