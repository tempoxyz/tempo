# TIP-1152: T14 Hardfork Meta TIP

## Abstract

The proposed T14 upgrade adds configurable accounts, state-gas accounting,
encrypted forced Zone withdrawals, and TIP-20 payment storage changes. This meta
TIP collects their specifications and implementation PRs alongside additional
T14-gated fixes and behavior changes. Inclusion here records proposed scope;
it does not approve a TIP or schedule activation.

## Motivation

Collect the T14 upgrade scope and implementation links in one place for review,
following the T12 and T13 meta TIPs.

## Assumptions

- Component proposals still follow [TIP-0000](./tip-0000.md). Their existing
  review status is preserved; a T14 implementation gate is not approval.
- Tempo and Zone operators coordinate fork schedules, portal runtime upgrades,
  compatible clients, and approved prover measurements before activation.
- PR and specification statuses below were checked on 2026-10-22. Open PRs can
  change; merged support code alone does not make a feature available.

# Additional T14 changes

These changes supplement the individual TIPs listed below and are proposed in
open implementation PRs. The intended fork gates preserve historical pre-T14 execution.

## 1. Bound validator endpoint lengths

**PRs**: [#8206](https://github.com/tempoxyz/tempo/pull/8206),
[#8554](https://github.com/tempoxyz/tempo/pull/8554) · **Author**: @hamdiallam (#8206), @decofe (#8554)

Amends [TIP-1017](./tip-1017.md): ValidatorConfig V2 rejects ingress or egress
inputs longer than 255 bytes with `InvalidIp` during add, rotate, and address
updates, before signature encoding. Malformed inputs within the limit retain
their existing format errors. #8554 centralizes the hardfork-aware parser and
has merged into #8206's branch, not `main`.

## 2. Default consensus to deferred verification after the fork boundary

**PR**: [#8438](https://github.com/tempoxyz/tempo/pull/8438) · **Author**: @decofe

Defaults `--consensus.verification-mode` to `hardfork`. Selects immediate or
deferred verification once per epoch using the previous epoch's finalized
boundary-block timestamp, or genesis for epoch zero. Deferred verification
starts when that timestamp reaches T14; explicit `immediate` and `deferred`
overrides remain available.

## 3. Pause Zone refund claims and batch settlement

**PR**: [#8295](https://github.com/tempoxyz/tempo/pull/8295) · **Author**: @decofe

The T14 portal runtime blocks refund claims and batch settlement while paused.
The sequencer idles batch preparation and submission until the portal resumes.
Older portal runtimes retain their existing behavior.

## 4. Charge sponsored Zone withdrawal fees in the default fee token

**PR**: [#8439](https://github.com/tempoxyz/tempo/pull/8439) · **Author**: @0xKitsune

A sponsored withdrawal burns its fee from the sponsor in the Zone default fee
token, captured from the portal's first enabled token at genesis. Unsponsored
withdrawals, including calls through a contract, burn principal plus fee from
the caller in the withdrawal token. The outbox and backing checker use the same
T14 gate.

## 5. Allow Zone TIP-20 transfers with portal-admin opt-in

**PR**: [#8549](https://github.com/tempoxyz/tempo/pull/8549) · **Author**: @adityapk00

Enables `transfer`, `transferFrom`, and their memo variants only when the Zone
runs T14 rules and the portal admin has enabled transfers. The setting defaults
to false and is read from finalized Tempo state. Transfers reject Permit2
callers, honor the token's L1 pause flag, and revert on receive-policy rejection
instead of diverting funds to `ReceivePolicyGuard`. Portal account access still
gates L1 addresses rather than Zone recipients.

## 6. Activate dynamic Zone base fees

**PR**: [#8401](https://github.com/tempoxyz/tempo/pull/8401) · **Author**: @adityapk00

Alongside TIP-1012's forced exits, #8401 activates the T7 dynamic base-fee
controller on Zones at T14, with a 0.6 gwei floor.

## Implementation links and open scope decisions

- **Forced exits:** [#8440](https://github.com/tempoxyz/tempo/pull/8440),
  [#8441](https://github.com/tempoxyz/tempo/pull/8441),
  [#8442](https://github.com/tempoxyz/tempo/pull/8442), and
  [#8443](https://github.com/tempoxyz/tempo/pull/8443) refine fee accounting,
  terminal outcomes, result events, and debit gas bounds. Portal admins must
  explicitly activate forced exits after the Zone is running T14 rules.
- **Configurable accounts:** commitment codec
  [#8474](https://github.com/tempoxyz/tempo/pull/8474), storage support
  [#8482](https://github.com/tempoxyz/tempo/pull/8482), recovery-factory plumbing
  [#8477](https://github.com/tempoxyz/tempo/pull/8477), and the unregistered
  precompile [#8486](https://github.com/tempoxyz/tempo/pull/8486) have merged to
  `main`. Full authorization [#7578](https://github.com/tempoxyz/tempo/pull/7578),
  pool revalidation [#7580](https://github.com/tempoxyz/tempo/pull/7580), and
  activation [#7581](https://github.com/tempoxyz/tempo/pull/7581) remain open.
  [#8557](https://github.com/tempoxyz/tempo/pull/8557) proposes preserving funded
  channel vouchers across migration;
  [#8562](https://github.com/tempoxyz/tempo/pull/8562) blocks configurable
  accounts on Zones until commitments can be synchronized.
- **Admin access keys:** [TIP-1137 / #8204](https://github.com/tempoxyz/tempo/pull/8204)
  is closed and is not included as an active T14 proposal. #7510 still references
  it; [#8566](https://github.com/tempoxyz/tempo/pull/8566) proposes retaining
  admin access keys. Resolve that specification mismatch before approval.
- **Provisional candidate:** [TIP-1148: Automatic Validator Fee Payouts](https://github.com/tempoxyz/tempo/blob/tip/1148/tips/tip-1148.md)
  is Draft / TBD in [#8333](https://github.com/tempoxyz/tempo/pull/8333).
  [#8330](https://github.com/tempoxyz/tempo/pull/8330) uses a provisional T14
  gate; this is not a decision to include it in T14.
- **TIP-20 storage:** [#8341](https://github.com/tempoxyz/tempo/pull/8341)
  preserves legacy execution and Zone policy support and has merged into
  #8293's branch, not `main`. The final portal runtime must combine these policy
  changes with the other agreed T14 portal changes.

# Tooling

Fork plumbing [#7910](https://github.com/tempoxyz/tempo/pull/7910) has merged to
`main`, exposing `t14Time` and `--t14-time`. Component TIPs define their SDK,
wallet, migration, and operator changes. Prover authentication and readiness
work is tracked in [#8391](https://github.com/tempoxyz/tempo/pull/8391),
[#8491](https://github.com/tempoxyz/tempo/pull/8491), and
[#8493](https://github.com/tempoxyz/tempo/pull/8493); approved measurements must
cover the final T14 execution rules.

# Observability

This inventory adds no protocol events. Component TIPs and implementation PRs
define events and metrics for their changes, including authenticated forced-exit
results and portal transfer opt-in updates.

# Threat Model

This meta TIP introduces no independent authority or execution path. Component
TIPs define their trust boundaries. Activation review must account for combined
portal runtime changes, account migration and delegated authority, token policy
conversion, and the prover images that authenticate the resulting execution.

# Invariants

- Pre-T14 blocks retain their historical execution rules.
- Genesis activation, fork-boundary upgrades, and new Zone deployments select
  compatible runtimes containing the agreed T14 changes together.
- Account migration cannot leave old root authority able to bypass new owners;
  any retained authority over already-funded channels is explicitly specified.
- Component approval, implementation merge, and network scheduling remain
  separate decisions; this inventory does not change their status.
