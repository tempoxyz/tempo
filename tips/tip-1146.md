# TIP-1146: T13 Meta TIP

## Abstract

T13 activates multi-block Tempo imports for Zones, native Nitro-backed batch
verification with a temporary proofless fallback, and explicit block system
calls. It also adds ordered fee-token fallback. This meta TIP links the
individual T13 TIPs and collects additional protocol changes.

## Motivation

This meta TIP collects the T13 upgrade scope and implementation links for review.

## Assumptions

Tempo and Zone operators coordinate activation, compatible settlement ABIs, and
prover builds. Nitro settlement requires approved release PCR measurements.

# T13 TIPs

The following TIPs are assigned to T13.

| TIP | Change |
| --- | --- |
| [TIP-1096: Multi-block Tempo Imports for Zones](./tip-1096.md) | Bounded header-only imports, full imports, and token-enablement cursor tracking. |
| [TIP-1098: Nitro-Backed Zone Batch Verification](./tip-1098.md) | Native Nitro verification, binding every settlement input including Zone height, and temporary `NoProof` fallback. |
| [TIP-1115: Ordered Fallback Fee Tokens](https://github.com/tempoxyz/tempo/pull/7597) | Tries `[pathUSD, OUSD]` in order when fee-token resolution reaches the fallback. |
| [TIP-1119: Explicit block system calls](./tip-1119.md) | Retains history and committee calls and omits Ethereum beacon-root and execution-request processing. |

# Additional protocol changes

These changes are not covered by an individual T13 TIP. They activate at T13;
pre-T13 behavior is unchanged. PR status records whether the implementation has
merged.

## 1. Use recipient policy for bridged TIP-20 credits

**PRs**: [#8286](https://github.com/tempoxyz/tempo/pull/8286) · **Author**: @decofe · **Status**: Merged

Zone deposits, withdrawal bounce-backs, and refund claims credit escrowed assets
using TIP-403 `Recipient` authorization instead of `MintRecipient`. Receive-policy
checks and refund behavior remain unchanged.
