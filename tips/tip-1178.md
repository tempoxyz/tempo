# TIP-1178: Zone Fees

## Abstract

This TIP turns on transaction fees on zones at T15. A zone block's base fee follows the [TIP-1067](./tip-1067.md) controller, as on L1. Fees MUST be paid in a TIP-20 whose `currency` is `USD`. The fee goes from the fee payer to the sequencer in that token, with no FeeAMM.

## Motivation

Zone blocks have a base fee of zero, so zone transactions cost nothing.

The zone fee manager converts a fee into token units as if one token were worth $1. A fee paid in a token worth $100 is 100× too high, and one paid in a token worth $0.001 is 1,000× too low. Accepting only USD tokens prevents both.

Two alternatives were considered. Running the FeeAMM on zones would let any enabled token pay fees, but it adds pools, liquidity and routing to every zone, so it is left out for now. A per-zone list of accepted fee tokens would close the gap in the Threat Model, where any token that declares `USD` passes, but it needs new configuration and an interface, so it is left to a later TIP.

## Assumptions

- A token can be used on a zone only after the zone admin enables it with `ZonePortal.enableToken`. This TIP assumes the admin enables only USD stablecoins worth $1. The protocol checks that a token declares `USD`, not what it is worth.
- Zones use TIP-1067's floor, cap and gas target unchanged.

# Specification

## Overview

T15 activates on a zone at the timestamp in its chainspec, or at L1's T15 timestamp when the zone genesis leaves it unset. From T15:

1. A zone block's base fee follows TIP-1067.
2. A fee token MUST be an initialized TIP-20 with `currency == "USD"`.
3. `ZoneFactory.createZone` MUST revert with `InvalidToken` when the initial token's `currency` is not `USD`, since the initial token becomes the zone's immutable default fee token ([TIP-1091](./tip-1091.md)).

Fee collection and sponsorship do not change. The fee payer pays. The zone fee manager escrows the maximum fee before execution, refunds the unused part afterwards, and pays the rest to the sequencer (the block beneficiary) in the same token.

## Mechanics

### Base fee

- Before T15, a zone block's `base_fee_per_gas` MUST be `0`.
- From T15, `base_fee_per_gas` MUST equal the TIP-1067 controller's output for the parent block's base fee and gas used. Pre-T15 blocks carry `0`, so the first block after activation starts at the floor. A zone that is T15 at genesis starts from the genesis header's base fee.
- A block whose header carries any other base fee is invalid.

### Fee token

A transaction's fee token is its `fee_token`, or the zone default when unset. It is checked in order:

1. It MUST have the TIP-20 address prefix.
2. It MUST be initialized. Otherwise the transaction is invalid with `InvalidFeeToken(token)`.
3. From T15, its `currency` MUST be exactly `USD`. Otherwise the transaction is invalid with `FeeTokenNotUsdCurrency { address, currency }`, the same check L1 applies.

### Transaction pool

From T15, the zone pool MUST reject a transaction whose `max_fee_per_gas` is below the TIP-1067 floor. A transaction at or above the floor but below the current base fee waits in the pool. Before T15, the pool accepts any fee cap.

Transactions admitted before T15 are not re-checked. One that fails the T15 fee-token check is dropped when a block builder rejects it. One whose fee cap is below the floor stays unexecutable until the sender replaces it or the pool evicts it.

### RPC

Once the latest block is a T15 block, `eth_gasPrice` returns the next block's base fee, and `eth_feeHistory` returns actual base fees while its gas used ratios and rewards stay redacted. `eth_fillTransaction` sets `max_fee_per_gas` to twice the next block's base fee, capped at the TIP-1067 cap, and the priority fee to `0`. Before then, these methods return the fixed pre-T15 values, which are above the floor, so a quote taken just before activation is still accepted.

## Interfaces

No new interfaces. `FeeTokenNotUsdCurrency` is the existing L1 error, and `createZone` reverts with the existing `InvalidToken` error.

# Compatibility

| Who | What changes from T15 |
| --- | --- |
| Zone users and wallets | A transaction needs a fee cap of at least the floor and a fee paid in an enabled USD token, by the sender or a sponsor. |
| Holders of non-USD tokens | Those tokens can no longer pay fees. They can still be transferred when the fee is paid in a USD token. |
| Sequencers | Fees arrive in whichever USD token each fee payer used. |
| Zone creators | `createZone` reverts unless the initial token is a USD token. A zone created before T15 with a non-USD initial token keeps it as its default fee token, so its transactions must set a USD `fee_token`. |

# Observability

N/A. Fees appear as TIP-20 `Transfer` events from the fee payer to the sequencer, and the base fee is in each block header, as on L1.

# Threat Model

| Threat | Defense | Remaining risk |
| --- | --- | --- |
| A token declares `USD` but is worth less than $1 | Only the zone admin can enable a token | If the admin enables one, fees paid in it are underpaid. Enabling cannot be undone. |
| Spam | The base fee never drops below the floor and rises with usage | Same cost as on L1 at the same usage. |
| An observer infers each block's gas used, which the zone RPC hides | Headers and `eth_feeHistory` still zero gas used | The controller is invertible: whenever the base fee moves between the floor and the cap, its change reveals the parent block's gas used. Accepted: from T15, a zone's per-block gas used is public through its base fee. |

Excluded: depegs. Every USD token is valued at $1, as on L1.

# Invariants

- Every zone block before T15 has `base_fee_per_gas == 0`. Every block from T15 has `floor ≤ base_fee_per_gas ≤ cap`, equal to the controller's output for its parent.
- Every transaction in a T15 zone block paid its fee in a TIP-20 whose `currency` is `USD`.
- For each transaction, the fee payer's net fee debit equals the sequencer's fee credit, and the fee manager's escrow balance is the same before and after.

Tests MUST cover:

- A non-USD fee token accepted before T15 and rejected from T15.
- The first block after activation having a base fee equal to the floor.
- A sponsored transaction charging the fee payer, not the sender.
