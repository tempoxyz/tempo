# TIP-1132: Key Publisher Precompile

## Abstract

Sign-in providers such as Google and Apple sign each ID token with one of a few signing keys, which they publish on their websites and replace from time to time. To accept a sign-in as a ZK signature ([TIP-1131](./tip-1131.md)), a Tempo node must know which keys are genuine, but it cannot fetch a website while validating a transaction. A key publisher solves this: it is an onchain list of a provider's current signing keys, which its owner, usually a wallet operator, keeps in sync with the provider's website.

Each account's address names the publisher it trusts. When the account signs, the node checks that the provider key behind the sign-in is on that publisher's list. Anyone can create a publisher, and a publisher can only affect the accounts that chose it. This TIP defines the Key Publisher precompile, a contract built into the node that stores these lists.

## Motivation

A ZK signature's proof shows that an issuer key with a given hash signed a statement, such as an ID token. Something onchain must say which key hashes belong to which issuer.

Publishers let wallets and users make that choice. A wallet picks a publisher, often one it runs, and each ZK signature address commits to that publisher's ID. A publisher can only affect addresses that name it.

### Success Criteria

[TIP-1130](./tip-1130.md#success-criteria) defines the feature's success criteria. For this component, the reference publisher lists a new provider key within 10 minutes of the provider publishing it.

## Assumptions

- Publisher owners list only genuine provider keys. A dishonest owner can forge ZK signatures for addresses that name its publisher.
- Issuers and key hashes are scheme-defined BN254 field elements. For OIDC, [TIP-1133](./tip-1133.md#hashing) defines them.
- When a listed provider key is compromised, the publisher owner revokes it.
- A creator that wants its publisher on several Tempo chains controls the same address on each of them.

# Specification

The key words "MUST", "MUST NOT", "SHOULD", and "MAY" are to be interpreted as described in RFC 2119.

## Precompile address

```solidity
address constant KEY_PUBLISHER_ADDRESS = 0x1132000000000000000000000000000000000000;
```

Implementations MUST use this address consistently across consensus, RPC, and tooling. The address is reserved by this TIP and subject to confirmation during implementation review.

## Constants

| Name | Value | Notes |
|---|---|---|
| `KEY_GRACE_PERIOD` | `3,600` seconds | How long a key dropped by `setKeys` stays valid |
| `MAX_KEYS_PER_ISSUER` | `16` | Microsoft's consumer endpoint listed 7 keys when surveyed |
| `ACTIVE` | `type(uint64).max` | `keyValidUntil` value of a listed key |
| `BN254_SCALAR_FIELD` | `21888242871839275222246405745257275088548364400416034343698204186575808495617` | |

`KEY_GRACE_PERIOD` is longer than the 600-second maximum window of TIP-1131's scheme `0x01`, so a sign-in in progress survives a routine rotation.

## Publisher IDs

```text
publisher_id = keccak256(abi.encode(creator, salt))
```

`creator` is the account that calls `createPublisher`, and `salt` is a `bytes32` value it chooses. Only `creator` can create a given ID, on any Tempo chain. A publisher serving accounts on several chains creates the same ID on each chain it supports. ZK signatures that name a publisher not yet created on a chain are rejected there.

## Interface

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

/// @title IKeyPublisher - TIP-1132 precompile interface
/// @notice Publishers list the identity-provider keys that ZK signatures may use.
///         Anyone can create a publisher. Only its owner can change its keys or owner.
interface IKeyPublisher {
    /// @notice An issuer and its key hashes, used to list a new publisher's first keys.
    struct IssuerKeys {
        bytes32 issuer;
        bytes32[] keyHashes;
    }

    /// @notice Emitted when a publisher is created.
    event PublisherCreated(bytes32 indexed publisherId, address indexed creator, address indexed owner);

    /// @notice Emitted when a publisher's owner changes.
    event OwnershipTransferred(bytes32 indexed publisherId, address indexed previousOwner, address indexed newOwner);

    /// @notice Emitted when an issuer's key list is replaced.
    /// @param keyHashes The new active keys, in ascending order.
    /// @param graceUntil The time until which keys dropped by this call stay valid.
    event KeysSet(bytes32 indexed publisherId, bytes32 indexed issuer, bytes32[] keyHashes, uint64 graceUntil);

    /// @notice Emitted when a key is revoked.
    event KeyRevoked(bytes32 indexed publisherId, bytes32 indexed issuer, bytes32 indexed keyHash);

    /// @notice The publisher already exists.
    error PublisherExists();

    /// @notice The publisher does not exist.
    error UnknownPublisher();

    /// @notice The caller is not the publisher's owner.
    error Unauthorized();

    /// @notice An owner argument is the zero address.
    error ZeroAddress();

    /// @notice An issuer or key hash is zero or not less than `BN254_SCALAR_FIELD`.
    error InvalidFieldElement();

    /// @notice `keyHashes` is not strictly ascending.
    error KeysNotSorted();

    /// @notice The issuers in `initialKeys` are not strictly ascending.
    error IssuersNotSorted();

    /// @notice `keyHashes` has more than `MAX_KEYS_PER_ISSUER` entries.
    error TooManyKeys();

    /// @notice The precompile was reached through `DELEGATECALL` or `CALLCODE`.
    error DelegateCallNotAllowed();

    /// @notice Creates the publisher `keccak256(abi.encode(msg.sender, salt))` with its first keys.
    ///         Any account may call it.
    /// @param salt Any value. The same caller and salt give the same ID on every chain.
    /// @param owner The account allowed to change the publisher. Any account, including a contract or multisig.
    /// @param initialKeys Each issuer's first key hashes, with issuers strictly ascending. May be empty.
    /// @return publisherId The new publisher's ID.
    function createPublisher(bytes32 salt, address owner, IssuerKeys[] calldata initialKeys)
        external
        returns (bytes32 publisherId);

    /// @notice Returns the ID that `creator` gets for `salt`.
    function computePublisherId(address creator, bytes32 salt) external pure returns (bytes32);

    /// @notice Transfers a publisher to a new owner, effective immediately.
    /// @dev Only the current owner may call it. Reverts with `ZeroAddress` if `newOwner` is zero.
    function transferOwnership(bytes32 publisherId, address newOwner) external;

    /// @notice Replaces an issuer's active keys.
    /// @dev Only the owner may call it. Listed keys become active. Previously active keys that are
    ///      not listed stay valid for `KEY_GRACE_PERIOD`. An empty list drops every key.
    /// @param issuer The scheme-defined issuer hash.
    /// @param keyHashes The scheme-defined key hashes, strictly ascending.
    function setKeys(bytes32 publisherId, bytes32 issuer, bytes32[] calldata keyHashes) external;

    /// @notice Revokes a key immediately, with no grace period. Only the owner may call it.
    function revokeKey(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external;

    /// @notice Returns a publisher's owner, or the zero address if the publisher does not exist.
    function owner(bytes32 publisherId) external view returns (address);

    /// @notice Returns an issuer's active keys in ascending order.
    function activeKeys(bytes32 publisherId, bytes32 issuer) external view returns (bytes32[] memory);

    /// @notice Returns the time until which a key is valid: `ACTIVE` while listed, a timestamp
    ///         during its grace period, or zero if it was never listed or was revoked.
    function keyValidUntil(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external view returns (uint64);

    /// @notice Returns whether ZK signatures may use a key in the current block.
    function isKeyActive(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external view returns (bool);
}
```

## Behavior

- **`createPublisher`** reverts with `ZeroAddress` if `owner` is zero, with `PublisherExists` if the ID already has an owner, and with `IssuersNotSorted` if the issuers in `initialKeys` are not strictly ascending. It validates each entry as `setKeys` validates its arguments. It then stores the owner, emits `PublisherCreated`, and lists each entry's keys as `setKeys` would, emitting `KeysSet` for each issuer. A publisher exists exactly when its stored owner is nonzero.
- **Owner checks.** `transferOwnership`, `setKeys`, and `revokeKey` revert with `UnknownPublisher` if the publisher does not exist, then with `Unauthorized` if `msg.sender` is not its owner.
- **`transferOwnership`** reverts with `ZeroAddress` if `newOwner` is zero. Otherwise it replaces the owner and emits `OwnershipTransferred`. Owners that want a two-step or delayed transfer can use a contract as the owner. A transfer applies only on the chain where it happens.
- **`setKeys`** validates its arguments before writing:
  - `issuer` and every key hash MUST be nonzero and less than `BN254_SCALAR_FIELD`, otherwise it reverts with `InvalidFieldElement`;
  - `keyHashes` MUST be strictly ascending, otherwise `KeysNotSorted`;
  - `keyHashes` MUST have at most `MAX_KEYS_PER_ISSUER` entries, otherwise `TooManyKeys`.

  It then:
  1. sets `keyValidUntil` to `block.timestamp + KEY_GRACE_PERIOD` for each key in the current active list that is not in `keyHashes`;
  2. sets `keyValidUntil` to `ACTIVE` for each key in `keyHashes`, including keys in a grace period and revoked keys;
  3. replaces the active list with `keyHashes` and emits `KeysSet` with `graceUntil = block.timestamp + KEY_GRACE_PERIOD`.

  Repeating a call with the same list changes no key status.
- **`revokeKey`** validates `issuer` and `keyHash` as `setKeys` does. It sets `keyValidUntil` to zero, removes the key from the active list if present, keeping the remaining keys in order, and emits `KeyRevoked`. Revoking an inactive key succeeds.
- **`isKeyActive`** returns `value != 0 && block.timestamp <= value`, where `value` is the key's `keyValidUntil`. A key is active while it is listed and during its grace period.
- **View functions** never revert for unknown publishers, issuers, or keys. They return zero values, an empty list, or `false`.
- **Delegate calls.** Every function MUST revert with `DelegateCallNotAllowed` when reached through `DELEGATECALL` or `CALLCODE`, detected as in other Tempo precompiles, so `msg.sender` is always the direct caller.
- State changes follow ordinary EVM revert semantics.

## Storage layout

Slots follow Solidity layout rules:

```solidity
mapping(bytes32 => address) owners;                                                // slot 0
mapping(bytes32 => mapping(bytes32 => bytes32[])) activeKeySets;                   // slot 1
mapping(bytes32 => mapping(bytes32 => mapping(bytes32 => uint64))) keyValidUntil;  // slot 2
```

## Node reads

TIP-1131 reads a key's status directly from storage at the transaction's position in the block, without calling the precompile:

```text
slot   = keccak256(key_hash . keccak256(issuer . keccak256(publisher_id . uint256(2))))
value  = uint64(sload(KEY_PUBLISHER_ADDRESS, slot))
active = value != 0 && block.timestamp <= value
```

Here `.` concatenates 32-byte words. A `setKeys` or `revokeKey` earlier in the same block applies to later transactions in that block.

Offchain verifiers of message signatures read the same slot at a past block ([TIP-1131](./tip-1131.md#message-signatures)).

## Gas

- Calls pay the [TIP-1100](./tip-1100.md) input charge and ordinary storage costs, including [TIP-1000](./tip-1000.md) creation costs for new slots. [TIP-1060](./tip-1060.md) storage credits apply as usual.
- A rotation that keeps the list length the same creates one new `keyValidUntil` slot, about 250,000 gas. Its other writes overwrite existing slots.
- Creating a publisher creates one owner slot, plus one list-length slot per initial issuer and two slots per initial key, each about 250,000 gas. One issuer with two keys costs about 1,500,000 gas.
- TIP-1131 charges the node's read as one cold storage read.

## Alternatives Considered

- **Validators fetching provider keys and agreeing on them.** This adds validator duties and makes the network decide which providers to trust.
- **An ordinary contract.** Nodes would have to execute EVM code during signature validation. A precompile has a fixed storage layout that nodes read directly.
- **Sequential publisher IDs.** ZK signature addresses are the same on every Tempo chain, so whoever first created a given sequential ID on another chain would control the addresses that name it there. An ID derived from its creator's address and a salt can only be created by that creator, on any chain.

# Tooling

- **Reference publisher job** (non-normative):
  - For each configured issuer, fetch `{iss}/.well-known/openid-configuration` and its `jwks_uri` at least every 5 minutes, honoring HTTP caching headers.
  - Keep keys with `kty` of `RSA`, `e` of `AQAB`, a 2048-bit modulus, `use` absent or `sig`, and `alg` absent or `RS256`. Compute their hashes as defined in TIP-1133.
  - Add a new key as soon as it appears. Drop a key once two consecutive fetches, at least 5 minutes apart, omit it, so one inconsistent response does not drop it.
  - A key a provider withdraws therefore stays usable for up to about 10 minutes, until the job drops it, plus `KEY_GRACE_PERIOD`: about 70 minutes in total unless the owner revokes it.
  - Alert when a provider key is missing onchain for more than 10 minutes, when an onchain key has been missing from the provider's list for more than 20 minutes, when fetches fail repeatedly, or when a key appears with an unexpected size or exponent.
- **Creators** create their publisher, with the same salt and their first keys, on each Tempo chain where their users hold accounts.
- **SDKs** expose this interface and helpers that compute `publisher_id`, `issuer`, and `key_hash`.
- **Wallets** show which publisher an account's ZK signatures name.

# Observability

| Event | Question it answers |
|---|---|
| `PublisherCreated` | Which publishers exist, who created them, and who owned them at creation? |
| `OwnershipTransferred` | Who controls a publisher now? |
| `KeysSet` | Which keys does a publisher list for an issuer, and when do dropped keys expire? |
| `KeyRevoked` | When did a key stop working? |

Indexers can rebuild each publisher's full history from these events.

# Threat Model

- **Publisher owner:** fully trusted by addresses that name its publisher. A compromised owner can list an attacker's key and forge ZK signatures for those addresses. Owners of publishers whose accounts hold significant value should be multisigs, timelocks, or both.
- **ID squatting:** an ID is derived from its creator's address, so no one else can create it on another chain and gain control of addresses that name it there.
- **Other callers** can create their own publishers and read state, but cannot change another publisher's keys or owner.
- **Rotation versus revocation:** a withdrawn key keeps working for up to about 70 minutes with the reference job, and a revoked key stops at once. Publisher owners revoke keys they believe are compromised.
- **Spam:** new publishers and keys pay for new storage slots. The 16-key limit per issuer bounds the work in `setKeys`.

# Invariants

- A publisher ID can only be created by the creator it is derived from, and only once per chain.
- Only a publisher's current owner can change its keys or owner.
- `isKeyActive` returns true exactly when the key's `keyValidUntil` is nonzero and at least the block timestamp.
- After `setKeys`, every listed key is `ACTIVE`, every dropped key expires at `block.timestamp + KEY_GRACE_PERIOD`, and every other key is unchanged.
- After `revokeKey`, the key is inactive and absent from the active list.
- Each active list is strictly ascending and holds at most 16 keys.
- Stored issuers and key hashes are nonzero and less than `BN254_SCALAR_FIELD`.
- The node's direct storage read agrees with `isKeyActive`.

Test cases MUST cover:

- creating an existing ID, and the same creator and salt producing the same ID as `computePublisherId`;
- creating a publisher with no initial keys, with several issuers, with unsorted or duplicate issuers, and with an invalid key list;
- a rotation, with the dropped key checked before, at, and after its grace boundary;
- re-listing a key in its grace period, and re-listing a revoked key;
- an empty list;
- unsorted, duplicate, zero, and out-of-field arguments, and 17 keys;
- calls from a non-owner, through `DELEGATECALL`, and from a previous owner after a transfer;
- `setKeys` and `revokeKey` followed by a ZK signature in the same block.
