# TIP-1132: Key Publisher Precompile

## Abstract

Sign-in providers such as Google and Apple sign ID tokens with a few signing keys, which they publish on their websites and replace from time to time. To accept a sign-in as a ZK signature ([TIP-1131](./tip-1131.md)), a node must know which keys are genuine, but it cannot fetch a website during validation. A key publisher is an onchain list of a provider's current keys, kept in sync by its owner, usually a wallet operator.

Each address names the publisher it trusts, and the node checks that the key behind a sign-in is on that publisher's list. Anyone can create a publisher, and a publisher affects only the addresses that name it. This TIP defines the precompile that stores these lists.

## Motivation

A ZK signature's proof shows that a key with a given hash signed a statement, so something onchain must say which key hashes belong to which issuer. Publishers let wallets make that choice instead of validators, and limit each publisher's reach to the addresses that name it.

## Assumptions

- Publisher owners list only genuine provider keys, and revoke keys they believe are compromised.
- Issuers and key hashes are scheme-defined BN254 field elements, defined for OIDC by [TIP-1133](./tip-1133.md#hashing).
- A creator serving several Tempo chains controls the same address on each.

# Specification

## Precompile address

```solidity
address constant KEY_PUBLISHER_ADDRESS = 0x1132000000000000000000000000000000000000;
```

## Constants

| Name | Value | Notes |
|---|---|---|
| `KEY_GRACE_PERIOD` | `3,600` seconds | How long a key dropped by `setKeys` stays valid; longer than scheme `0x01`'s 600-second window |
| `MAX_KEYS_PER_ISSUER` | `16` | Microsoft's consumer endpoint listed 7 keys when surveyed |
| `ACTIVE` | `type(uint64).max` | `keyValidUntil` of a listed key |
| `BN254_SCALAR_FIELD` | `21888242871839275222246405745257275088548364400416034343698204186575808495617` | |

## Publisher IDs

```text
publisher_id = keccak256(abi.encode(creator, salt))
```

`creator` is the caller of `createPublisher`, and `salt` is a `bytes32` it chooses, so only `creator` can create a given ID on any chain. A publisher serving several chains creates the same ID on each. ZK signatures naming a publisher that does not exist on a chain are rejected there.

## Interface

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

/// @title IKeyPublisher - TIP-1132 precompile interface
/// @notice Publishers list the identity-provider keys that ZK signatures may use.
///         Anyone can create a publisher. Only its owner can change its keys or owner.
interface IKeyPublisher {
    /// @notice An issuer and its key hashes, used to list a new publisher's first keys.
    struct IssuerKeys {
        bytes32 issuer;
        bytes32[] keyHashes;
    }

    /// @notice Emitted when a publisher is created.
    event PublisherCreated(bytes32 indexed publisherId, address indexed creator, address indexed owner);

    /// @notice Emitted when a publisher's owner changes.
    event OwnershipTransferred(bytes32 indexed publisherId, address indexed previousOwner, address indexed newOwner);

    /// @notice Emitted when an issuer's key list is replaced.
    /// @param keyHashes The new active keys, in ascending order.
    /// @param graceUntil The time until which keys dropped by this call stay valid.
    event KeysSet(bytes32 indexed publisherId, bytes32 indexed issuer, bytes32[] keyHashes, uint64 graceUntil);

    /// @notice Emitted when a key is revoked.
    event KeyRevoked(bytes32 indexed publisherId, bytes32 indexed issuer, bytes32 indexed keyHash);

    /// @notice The publisher already exists.
    error PublisherExists();

    /// @notice The publisher does not exist.
    error UnknownPublisher();

    /// @notice The caller is not the publisher's owner.
    error Unauthorized();

    /// @notice An owner argument is the zero address.
    error ZeroAddress();

    /// @notice An issuer or key hash is zero or not less than `BN254_SCALAR_FIELD`.
    error InvalidFieldElement();

    /// @notice `keyHashes` is not strictly ascending.
    error KeysNotSorted();

    /// @notice The issuers in `initialKeys` are not strictly ascending.
    error IssuersNotSorted();

    /// @notice `keyHashes` has more than `MAX_KEYS_PER_ISSUER` entries.
    error TooManyKeys();

    /// @notice The precompile was reached through `DELEGATECALL` or `CALLCODE`.
    error DelegateCallNotAllowed();

    /// @notice Creates the publisher `keccak256(abi.encode(msg.sender, salt))` with its first keys.
    /// @param salt Any value. The same caller and salt give the same ID on every chain.
    /// @param owner The account allowed to change the publisher, such as a multisig.
    /// @param initialKeys Each issuer's first key hashes, with issuers strictly ascending. May be empty.
    /// @return publisherId The new publisher's ID.
    function createPublisher(bytes32 salt, address owner, IssuerKeys[] calldata initialKeys)
        external
        returns (bytes32 publisherId);

    /// @notice Returns the ID that `creator` gets for `salt`.
    function computePublisherId(address creator, bytes32 salt) external pure returns (bytes32);

    /// @notice Transfers a publisher to a new owner, effective immediately. Only the owner may call it.
    function transferOwnership(bytes32 publisherId, address newOwner) external;

    /// @notice Replaces an issuer's active keys. Only the owner may call it.
    /// @dev Listed keys become active. Previously active keys that are not listed stay valid
    ///      for `KEY_GRACE_PERIOD`. An empty list drops every key.
    /// @param keyHashes The scheme-defined key hashes, strictly ascending.
    function setKeys(bytes32 publisherId, bytes32 issuer, bytes32[] calldata keyHashes) external;

    /// @notice Revokes a key immediately, with no grace period. Only the owner may call it.
    function revokeKey(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external;

    /// @notice Returns a publisher's owner, or the zero address if it does not exist.
    function owner(bytes32 publisherId) external view returns (address);

    /// @notice Returns an issuer's active keys in ascending order.
    function activeKeys(bytes32 publisherId, bytes32 issuer) external view returns (bytes32[] memory);

    /// @notice Returns `ACTIVE` while a key is listed, the end of its grace period after it is
    ///         dropped, or zero if it was never listed or was revoked.
    function keyValidUntil(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external view returns (uint64);

    /// @notice Returns whether ZK signatures may use a key in the current block.
    function isKeyActive(bytes32 publisherId, bytes32 issuer, bytes32 keyHash) external view returns (bool);
}
```

## Behavior

- **`createPublisher`** reverts with `ZeroAddress` if `owner` is zero, `PublisherExists` if the ID has an owner, and `IssuersNotSorted` unless the issuers are strictly ascending. It validates each entry as `setKeys` does, stores the owner, emits `PublisherCreated`, and lists each issuer's keys as `setKeys` would. A publisher exists exactly when its owner is nonzero.
- **Owner checks.** `transferOwnership`, `setKeys`, and `revokeKey` revert with `UnknownPublisher` if the publisher does not exist, then `Unauthorized` unless `msg.sender` is its owner.
- **`transferOwnership`** reverts with `ZeroAddress` if `newOwner` is zero, and otherwise replaces the owner on that chain only. Two-step or delayed transfers use a contract as the owner.
- **`setKeys`** reverts with `InvalidFieldElement` unless `issuer` and every key hash are nonzero and less than `BN254_SCALAR_FIELD`, `KeysNotSorted` unless `keyHashes` is strictly ascending, and `TooManyKeys` above `MAX_KEYS_PER_ISSUER`. It then:
  1. sets `keyValidUntil` to `block.timestamp + KEY_GRACE_PERIOD` for each active key not in `keyHashes`;
  2. sets `keyValidUntil` to `ACTIVE` for each key in `keyHashes`, including keys in a grace period and revoked keys;
  3. replaces the active list and emits `KeysSet`.
- **`revokeKey`** validates its arguments as `setKeys` does, sets `keyValidUntil` to zero, removes the key from the active list while keeping the others in order, and emits `KeyRevoked`. Revoking an inactive key succeeds.
- **`isKeyActive`** returns `value != 0 && block.timestamp <= value`, where `value` is the key's `keyValidUntil`.
- **View functions** never revert. Unknown entries return zero values, an empty list, or `false`.
- **Delegate calls.** Every function reverts with `DelegateCallNotAllowed` through `DELEGATECALL` or `CALLCODE`, so `msg.sender` is always the direct caller.

## Storage layout

Slots follow Solidity layout rules:

```solidity
mapping(bytes32 => address) owners;                                                // slot 0
mapping(bytes32 => mapping(bytes32 => bytes32[])) activeKeySets;                   // slot 1
mapping(bytes32 => mapping(bytes32 => mapping(bytes32 => uint64))) keyValidUntil;  // slot 2
```

## Node reads

TIP-1131 reads a key's status from storage at the transaction's position in the block, without calling the precompile:

```text
slot   = keccak256(key_hash . keccak256(issuer . keccak256(publisher_id . uint256(2))))
value  = uint64(sload(KEY_PUBLISHER_ADDRESS, slot))
active = value != 0 && block.timestamp <= value
```

Here `.` concatenates 32-byte words. A `setKeys` or `revokeKey` earlier in a block applies to later transactions in it. Offchain verifiers of [message signatures](./tip-1131.md#message-signatures) read the same slot at a past block.

## Gas

- Calls pay the [TIP-1100](./tip-1100.md) input charge and ordinary storage costs, including [TIP-1000](./tip-1000.md) creation costs. [TIP-1060](./tip-1060.md) credits apply.
- A rotation that keeps the list length creates one `keyValidUntil` slot, about 250,000 gas.
- Creating a publisher creates one owner slot, one list-length slot per issuer, and two slots per key, about 250,000 gas each: about 1,500,000 gas for one issuer with two keys.
- TIP-1131 charges the node read as one cold storage read.

## Alternatives Considered

- **Validators syncing provider keys:** adds validator duties and makes the network choose providers.
- **An ordinary contract:** nodes would execute EVM code during signature validation. A precompile has a fixed layout that nodes read directly.
- **Sequential IDs:** addresses are the same on every chain, so whoever first created an ID on another chain would control the addresses that name it there.

# Tooling

- **Reference publisher job** (non-normative): every 5 minutes, fetch each issuer's discovery document and `jwks_uri`. Keep RSA keys with `e` of `AQAB`, a 2048-bit modulus, `use` absent or `sig`, and `alg` absent or `RS256`. Add new keys at once, and drop a key after two consecutive fetches omit it. A withdrawn key then stays usable for about 70 minutes unless revoked.
- **Creators** create their publisher, with the same salt and first keys, on each chain where their users hold accounts.
- **SDKs** expose this interface and helpers for `publisher_id`, `issuer`, and `key_hash`. Wallets show which publisher an address names.

# Observability

| Event | Question it answers |
|---|---|
| `PublisherCreated` | Which publishers exist, and who created and first owned them? |
| `OwnershipTransferred` | Who controls a publisher? |
| `KeysSet` | Which keys are listed, and when do dropped keys expire? |
| `KeyRevoked` | When did a key stop working? |

Publishers SHOULD alert when a provider key is missing onchain for more than 10 minutes, an onchain key is missing from the provider's list for more than 20 minutes, fetches fail repeatedly, or a key has an unexpected size or exponent.

# Threat Model

- **Publisher owner:** fully trusted by addresses that name its publisher, since a compromised owner can list an attacker's key. Publishers whose addresses hold significant value should use multisig or timelock owners.
- **Other callers** can create publishers and read state, but cannot change another publisher or create its ID on another chain.
- **Withdrawn keys** keep working for about 70 minutes with the reference job. Revocation stops a key at once.
- **Spam:** new publishers and keys pay for storage, and the 16-key limit bounds `setKeys`.

# Invariants

- A publisher ID can be created only by its creator, once per chain.
- Only the current owner can change a publisher's keys or owner.
- After `setKeys`, listed keys are `ACTIVE`, dropped keys expire at `block.timestamp + KEY_GRACE_PERIOD`, and other keys are unchanged.
- After `revokeKey`, the key is inactive and unlisted.
- Active lists are strictly ascending, hold at most 16 keys, and contain only nonzero field elements.
- The node's storage read agrees with `isKeyActive`.

## Test Cases

- Creating an existing ID, and IDs matching `computePublisherId`.
- Creating with no keys, several issuers, unsorted or duplicate issuers, and invalid key lists.
- A rotation, checking the dropped key before, at, and after its grace boundary.
- Re-listing a key in its grace period and a revoked key, and setting an empty list.
- Unsorted, duplicate, zero, and out-of-field arguments, and 17 keys.
- Calls from a non-owner, a previous owner, and through `DELEGATECALL`.
- `setKeys` and `revokeKey` followed by a ZK signature in the same block.
