Some groups span multiple paragraphs; the mapping above explicitly identifies them. Requirements have stable IDs and named cases with separate T11/T12/T13 suffixes for each declared fork obligation; unmeasured cases remain declared gaps.

`quote_exact_in` and `quote_exact_out` gate their per-order walker at `self.storage.spec().is_t12()`, preserving their legacy per-tick else branches. The unconditional `quote_per_order` helper is called only by those gates. It uses `walk_resting_orders` with `step_exact_in/out` and a callback that only advances via `next_order_after`. Execute uses that same walker and arithmetic with `settle_fill`, then partial/full settlement. These are callback-selected simulation/execution modes, not an enum named Simulate/Execute. The helper's `gate=always` annotation describes the helper body, not pre-T12 quote applicability.

`next_order_after` follows next order, then the next initialized tick; full execution advances similarly. The common walker uses checked accumulation and returns InsufficientLiquidity on exhausted orders with residual requested amount. Settlement occurs before accumulation overflow, preserving historical ordering. Fixed observed prices are regression evidence, not a proof of unchanged prices for every order/input.

T12 aggregate maintenance gates exist on placement, partial fill, full fill and cancellation; flip placement shares the placement path. TickLevelHandler read/write/delete preserve the storage layout and skip the aggregate slot at T12. `get_price_level` traverses the active linked list with checked addition. The write paths inspected update links and amounts without summing the linked list. The layout test carries actual T11 aggregate storage into T12, cancels, places and exhausts orders, and observes the unchanged raw aggregate via Handler UFCS. It also creates two individually valid orders whose sum overflows, then observes the checked read failure. No migration runs between forks.

The `fill_order` error branch swallows business flip errors and propagates system errors at T1A+, and this branch is reached only from Execute settlement. Quote does not call flip placement. External shapes are unchanged by this patch; get_price_level and the existing conversion to IStablecoinDEX TickLevel retain their established fields. This source review does not substitute for ABI compatibility tests.

## Evidence and limitations

Ignored `spec_dashboard_dex_t11/t12/t13` tests directly observe quotes/swaps, with fresh deterministic amount/tick books (actor addresses are randomized but not price inputs). T11 retains the one-unit quote drift; all forks preserve the independently calculated 200032000 execution result. T12/T13 finite cases exercise bids/asks, exact in/out, partial/full and multiple-tick fills with tight slippage and excessive-liquidity requests. Separate T12 tests cover two-hop routes, flip-order traversal, stale slots, and checked aggregate overflow. `spec_evidence!` evaluates one assertion before printing a JSON line; no file IO occurs in it. Output identifies the fully qualified test and the literal fork actually supplied to its environment. Default tests exclude these ignored tests; explicit ignored selection is required.

Persistent write evidence compares the real HashMapStorageProvider SSTORE counter before/after quote, including writes restored to the same value. Events compare actual emitted DEX log snapshots. Flip evidence additionally checks the original side/tick remains before execution. These checks do not inspect all token-address logs or count transient writes. The provider's gas-refund method is a no-op, so comparing its refund value would be false evidence and is deliberately omitted. R5 therefore retains no_transient_writes and no_refunds_discounts runtime gaps. Source inspection finds the quote callback has no settlement, credit or flip-gas calls, but an EVM-backed instrumented test is still required for those claims.

R6 write_paths_no_traversal is source-reviewed but lacks an isolated operation-count/runtime case for every path, especially flip placement. R8 api_shapes is source-reviewed only. R9 business_flip_failure/system_flip_failure have no new fault-injection evidence and remain gaps. R10 caller_gas_guidance is a normative caller recommendation with no runtime implementation assertion. There is no claim of complete dynamic verification of the TIP. Fixed finite tests do not prove all-input parity, all possible overflow boundaries, token-specific behavior, or system-error outcomes. T13 coverage covers the core cases; layout/flip/multi-hop cases currently execute only at T12.
