# TIP-1116: T12 Hardfork Meta TIP

## Abstract

This meta TIP collects changes proposed for the T12 hardfork and links their
implementations. These changes relax trailing-byte validation in precompile ABI
decoding while retaining the other strict decoding checks introduced at T11, and
activate V1 DKG reveals and V1 leader election at their starting boundaries.

## Motivation

A shared T12 tracking document makes the proposed upgrade scope and implementation
dependencies reviewable. Allowing trailing ABI bytes restores compatibility for
otherwise valid precompile calls that include a suffix, without removing the
remaining decoding checks described in [TIP-1105](./tip-1105.md).
Pinning the consensus version changes to ceremony and epoch starting boundaries
preserves consistency across mid-epoch activation, restarts, and historical share
recovery.

# Changes

## 1. Allow trailing ABI bytes in precompile calls

**PRs**: [#7598](https://github.com/tempoxyz/tempo/pull/7598) · **Author**: @klkvr

From T12, Tempo precompile dispatchers enable Alloy's
`validate_allow_trailing_bytes` option alongside the strict ABI validation enabled
at T11. Otherwise valid ABI arguments may be followed by unused trailing bytes;
strict validation of the decoded arguments remains enabled, including rejection
of gaps and truncation. The existing 16 MiB decoder memory limit remains in place.

Pre-T12 behavior is unchanged: T11 retains strict decoding without trailing-byte
acceptance, and earlier hardforks retain their historical decoding behavior.

## 2. Activate DKG reveal V1

**PRs**: [#7790](https://github.com/tempoxyz/tempo/pull/7790) · **Author**: @hamdiallam

DKG ceremonies whose starting boundary has T12 active use `Reveal::V1`; earlier
ceremonies retain V0. Pinning the reveal version to the ceremony's starting
boundary preserves transcript compatibility across mid-epoch activation,
restarts, and historical share recovery.

## 3. Activate V1 leader election

**PRs**: [#7810](https://github.com/tempoxyz/tempo/pull/7810) · **Author**: @hamdiallam

Epochs whose starting boundary has T12 active use `RandomVersion::V1` for leader
election; earlier epochs retain V0. Selecting the version from the preceding
finalized boundary keeps leader selection consistent across nodes and restarts.
