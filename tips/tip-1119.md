# TIP-1119: Explicit block system calls

## Abstract

This TIP limits Tempo's automatic block system calls to storing parent block hashes
and updating the committee. It disables Ethereum's beacon-root and execution-request
calls.

## Motivation

Tempo inherits Ethereum's system calls and validation through its block executor.
[Alloy-evm #400](https://github.com/alloy-rs/evm/pull/400) rejects Amsterdam blocks
when either builder contract is missing. Tempo should explicitly select its history
and committee calls instead of inheriting Ethereum's selection or checking for code
at each target.

## Assumptions

The history contract accepts the EIP-2935 parent-hash input. The committee call
accepts the epoch and ordered players from the DKG outcome selected by consensus,
as specified by [TIP-1070](./tip-1070.md). Interface changes require corresponding
updates to these rules.

## Threat Model

A proposer or contract deployer cannot enable additional automatic system calls.
Validators apply the same fork rules regardless of code at excluded addresses.
Ordinary transaction calls to those addresses remain subject to normal EVM rules.

# Specification

## System calls

At T13, replace Ethereum's automatic block system-call selection with the following
rules:

| Call | Timing | Caller | Target | Input |
| --- | --- | --- | --- | --- |
| EIP-2935 history update | Before transactions, except genesis; existing Prague gate applies | `0xfffffffffffffffffffffffffffffffffffffffe` | `0x0000F90827F1C53a10cb7A02335B175320002935` | Parent block hash as 32 raw bytes |
| Current committee update ([TIP-1070](./tip-1070.md)) | After transactions in the last block of an epoch; existing T8 gate applies | `0x0000000000000000000000000000000000000000` | `0xC077E00000000000000000000000000000000000` | ABI-encoded `setCommitteeMembers(uint64 epoch, bytes32[] publicKeys)` from the block's DKG outcome |

The executor commits the state returned by the history call. EVM invocation or
database errors abort block processing. A returned EVM revert or halt does not
invalidate the block. Missing history code produces no update. Tempo initialization
and precompile deployment follow the history call and precede transactions.

The last block of epoch `E` is the block at height `h` where
`h % epoch_length == epoch_length - 1`.

The call runs after incentive-section gas validation. Failure to decode the required
DKG outcome, an EVM invocation error, or a reverted or halted committee call aborts
block processing. On success, the executor commits the returned state.

Transactions in the last block of epoch `E` MUST continue to observe the committee for
epoch `E`; the persisted committee record for epoch `E+1` MUST only become visible to
user EVM execution in the first block of epoch `E+1`.

These calls do not add transactions or receipts and do not consume block gas
capacity.

## Excluded Ethereum processing

The executor MUST NOT schedule the EIP-4788 beacon-root call, EIP-7002 withdrawal
request call, EIP-7251 consolidation request call, or either EIP-8282 builder
request call. It MUST NOT require code at those targets or a beacon root for the
omitted call, regardless of target code or Amsterdam activation.

The executor MUST NOT parse EIP-6110 deposit logs into execution requests. The
execution-request list MUST be empty.

The executor MUST NOT apply Ethereum block or ommer rewards, withdrawal balance
increments, or the DAO transition. Nonempty withdrawals remain invalid.

Receipts retain their order, logs, status, and cumulative gas. Header gas used
remains regular execution gas when [TIP-1016](./tip-1016.md) is enabled and
cumulative transaction gas after refunds otherwise.

## Activation and Compatibility

The rule activates at T13. Before T13, blocks MUST be processed according to the
existing rules. At and after T13, blocks MUST use the system-call selection
specified above.

- `TEMPO-SYSCALL-PRE-T13-UNCHANGED`: Before T13, `apply_pre_execution_changes` and `finish` run the inherited Ethereum executor's system calls, request parsing and post-block processing unchanged.
  - Checked by: `crates/evm/src/block.rs::test_system_calls_activation_selects_history_only`
- `TEMPO-SYSCALL-HISTORY-PARENT-HASH`: At T13 and later, for every block with `number > 0` while Prague is active, the executor calls `HISTORY_STORAGE_ADDRESS` (EIP-2935) from `0xfffffffffffffffffffffffffffffffffffffffe` with the 32-byte parent hash as input before any transaction and commits the returned state.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_activation_selects_history_only`
- `TEMPO-SYSCALL-HISTORY-GENESIS-AND-NO-CODE`: At T13 and later, the genesis block makes no history call and a block whose `HISTORY_STORAGE_ADDRESS` has no code records no parent hash and is still valid.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_history_genesis_and_missing_code`
- `TEMPO-SYSCALL-HISTORY-PRAGUE-GATE`: At T13 and later, no history call is made while Prague is not active.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_history_respects_prague_gate`
- `TEMPO-SYSCALL-HISTORY-REVERT-KEEPS-BLOCK`: At T13 and later, a history call that reverts or halts leaves no state change and does not invalidate the block, while an EVM invocation or database error aborts block processing.

  - Checked by: `crates/evm/src/block.rs::test_system_calls_history_revert_and_halt_are_not_block_errors`
- `TEMPO-SYSCALL-EXCLUDED-TARGETS`: At T13 and later, the executor makes no automatic call to the EIP-4788 beacon-roots, EIP-7002 withdrawal-request, EIP-7251 consolidation-request or EIP-8282 builder deposit and exit request contracts, whatever code they hold and even with Amsterdam active.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_activation_selects_history_only`
- `TEMPO-SYSCALL-NO-CODE-REQUIRED`: At T13 and later, a block is valid without code at any excluded system-call target and without a parent beacon block root, even with Amsterdam active.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_history_genesis_and_missing_code`
- `TEMPO-SYSCALL-NO-DEPOSIT-REQUESTS`: At T13 and later, logs shaped like EIP-6110 deposit events stay ordinary receipt logs and the block's execution-request list is empty.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_skips_ethereum_deposit_parsing`
- `TEMPO-SYSCALL-COMMITTEE-PRESERVED`: At T13 and later, the TIP-1070 committee update remains the only post-transaction system call and still runs after all transactions of an epoch's last block, so that block's transactions read the previous committee and the next block reads the new one.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_finish_preserves_committee_update`
- `TEMPO-SYSCALL-NO-REWARDS-OR-DAO`: At T13 and later, the executor applies no Ethereum block or ommer reward and no DAO-fork balance transfer.
  - Since: T13
  - Checked by: `crates/evm/src/block.rs::test_system_calls_disables_rewards_and_dao_only_after_activation`
- `TEMPO-SYSCALL-NO-WITHDRAWALS`: `apply_pre_execution_changes` rejects any block with a nonempty withdrawals list with "withdrawals are not permitted".
  - Checked by: `crates/evm/src/block.rs::test_system_calls_rejects_withdrawals_and_incentive_overflow`
- `TEMPO-SYSCALL-INCENTIVE-GAS-ZERO`: `finish` rejects a block whose incentive section used any gas with "incentive gas limit exceeded", before running the committee system call.
  - Since: T4
  - Checked by: `crates/evm/src/block.rs::test_system_calls_rejects_withdrawals_and_incentive_overflow`

  - Checked by: `crates/evm/src/block.rs::test_system_calls_finish_preserves_receipts_and_gas`

  - Since: T13
