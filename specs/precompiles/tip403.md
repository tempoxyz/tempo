# TIP-403 Registry, ReceivePolicyGuard and AddressRegistry

This chapter specifies three precompiles that together decide whether TIP-20 value may move between two addresses:

- **TIP403Registry** (`0x403C000000000000000000000000000000000000`): transfer policies (simple whitelist/blacklist, built-in policies, TIP-1015 compound policies from T2), TIP-1028 account receive policies (from T6), and TIP-1092 token→policy bindings (from T9).
- **ReceivePolicyGuard** (`0xB10C000000000000000000000000000000000000`, from T6): custody of inbound TIP-20 transfers and mints blocked by a receiver's receive policy, and their claim or burn.
- **AddressRegistry** (`0xFDC0000000000000000000000000000000000000`, from T3): TIP-1022 virtual-address masters and recipient resolution, and the TIP-1035 implicit-approval list (from T5).

The TIP-20 side of these features (where the token calls the registry, the divert of a blocked inbound to the guard, `burnBlocked`, the effective transfer-policy rule) is specified in precompiles/tip20.md; this chapter defines the operations it calls, by name.

Everything in this chapter applies to Tempo mainnet (chain 4217) from genesis. Fork predicates ("From T6:", "Before T2:") are defined in 01-chain-and-forks.md: fork F is active iff `header.timestamp >= F's activation time`. Moderato uses the same rules at its own fork timestamps.

Reference implementation: crates/precompiles/src/tip403_registry/, crates/precompiles/src/receive_policy_guard/, crates/precompiles/src/address_registry/, crates/contracts/src/precompiles/{tip403_registry,receive_policy_guard,address_registry}.rs.

## 1. Conventions

The precompile call framework (input charge, selector dispatch, ABI decoding per fork, static-call rejection, revert encoding, storage gas, logs) is defined in precompiles/00-framework.md. This chapter uses the following notation on top of it.

- `sload(A, k)` / `sstore(A, k, v)`: read / write storage word `k` of account `A`, charged as storage accesses per precompiles/00-framework.md (EIP-2929 warm/cold accounting keyed by `(A, k)`, Tempo's SSTORE pricing). Every storage access listed in the algorithms below MUST be performed, and no others, in the listed order: the sequence determines gas used and therefore block validity.
- `mslot(key, p)` = `keccak256(pad32(key) ‖ uint256_be(p))`, the slot of a mapping entry whose mapping is at slot `p`. `pad32(key)` is the key's own big-endian bytes **left-padded with zeros** to 32 bytes: a `uint64` key is its 8 big-endian bytes, an `address` its 20 bytes, a `bytes32` key itself, and a `bytes4` key is `0x00…00 (28 bytes) ‖ key (4 bytes)`. For `bytes4` this differs from Solidity, which left-aligns `bytesN` (key encoding as in precompiles/00-framework.md §6.5). The hash in `mslot` is **not** gas-charged. Nested mappings compose: `m[a][b]` is at `mslot(b, mslot(a, p))`.
- Packed words: a struct's fields are packed into 32-byte words in declaration order starting at the least-significant byte ("byte offset 0" = the lowest-order byte, Solidity layout). A field that does not fit the remaining bytes starts a new word; a nested struct starts a new word.
- `write_struct_word(A, k, fields)`: writing a whole packed struct word. **Before T4:** `w = sload(A, k)`, overwrite only the bytes the fields occupy, then `sstore(A, k, w)` (unowned padding bytes keep their old value). **From T4:** `sstore(A, k, w)` where `w` holds the fields and zero padding, with no prior `sload`. A field that is the only occupant of its word is written with a plain `sstore` at every fork.
- `keccak_charged(data)`: keccak256 whose cost `30 + 6·⌈len(data)/32⌉` gas is deducted from the frame (out of gas halts per the framework). Only where this chapter says `keccak_charged` is a hash charged.
- `account_code_check(A)`: loads account `A` and tests whether its code hash is non-empty; charged as an account access per precompiles/00-framework.md.
- `emit(A, Event(...))`: appends a log from address `A` with Solidity event encoding (topic0 = keccak256 of the signature; indexed static arguments are topics, each ABI-encoded in one word; the rest is ABI-encoded data).
- `revert(E)`: the precompile reverts with the ABI encoding of error `E` (4-byte selector ‖ arguments). `Panic(0x11)` is `0x4e487b71 ‖ uint256(0x11)`.
- **Internal operations.** Other precompiles (TIP-20, StablecoinDEX, TipFeeManager, TIP20ChannelReserve, ZoneFactory/Portal) invoke the operations in sections 3.4, 4.4 and 5.5 directly, not through a CALL: no input charge, no selector gating, no new frame. Their storage accesses and charged hashes are counted in the calling frame, and their reverts propagate as the caller's revert.

Unless stated otherwise, `fork` in pseudocode is the active fork of the block being executed.

## 2. Addresses, activation and selector schedule

| Precompile | Address | Active from | Genesis state (mainnet) |
|---|---|---|---|
| TIP403Registry | `0x403C000000000000000000000000000000000000` | Genesis | code `0xEF`, no storage |
| AddressRegistry | `0xFDC0000000000000000000000000000000000000` | T3 | none; code `0xEF` installed at the first T3 block |
| ReceivePolicyGuard | `0xB10C000000000000000000000000000000000000` | T6 | none; code `0xEF` installed at the first T6 block |

Before its activation fork an address is not a precompile (calls to it are calls to an ordinary account; see precompiles/00-framework.md). The one-byte `0xEF` code marker is written, in the pre-execution changes of every block where the fork is active, if the account's code is empty, keeping its balance and nonce and writing no storage (05-block-execution.md). No storage of these precompiles is initialized at activation: in particular the guard's nonce slot stays 0 (section 4.2).

Selectors whose fork is not yet active MUST be rejected before argument decoding with `UnknownFunctionSelector(bytes4 selector)` (encoding per precompiles/00-framework.md), exactly as for a selector the interface does not define, even when the arguments are malformed. The fork column below is the first fork at which each selector is dispatched.

**Enum argument decoding.** `policyType` arguments are decoded per the fork's ABI decoder configuration (precompiles/00-framework.md). Before T11 (non-strict decoding) the value is the low-order byte of the argument word; bytes `0, 1, 2` decode to `WHITELIST, BLACKLIST, COMPOUND` and any other byte decodes to the out-of-range value `INVALID = 255`. From T11 (strict decoding) a word that is not `0, 1` or `2` makes decoding fail (empty revert), so `INVALID` never reaches a handler.

## 3. TIP403Registry

### 3.1 Constants and types

```python
REGISTRY = 0x403C000000000000000000000000000000000000
GUARD    = 0xB10C000000000000000000000000000000000000
ADDRESS_REGISTRY = 0xFDC0000000000000000000000000000000000000
M64 = 2**64 - 1

def has_tip20_prefix(a): return a[0:12] == bytes.fromhex("20C000000000000000000000")

REJECT_ALL_POLICY_ID = 0      # built-in: every check returns False
ALLOW_ALL_POLICY_ID  = 1      # built-in: every check returns True
FIRST_USER_POLICY_ID = 2

WHITELIST, BLACKLIST, COMPOUND = 0, 1, 2   # PolicyType
INVALID_TYPE = 255                          # pre-T2 stored value for COMPOUND / out-of-range input
NONE, TOKEN_FILTER, RECEIVE_POLICY = 0, 1, 2   # BlockedReason
ORIGINATOR, RECEIVER, THIRD_PARTY = 0, 1, 2    # RecoveryMode (u8)

# Authorization roles (internal; not ABI)
TRANSFER, SENDER, RECIPIENT, MINT_RECIPIENT = range(4)

# From T6: addresses that every policy authorizes in every role.
def always_authorized(user):
    return fork >= T6 and user == GUARD
```

**Role selection by fork.** Callers that ask for a directional role MUST use the following, so that before T2 every check is the symmetric `TRANSFER` role:

```python
def role_sender():         return SENDER         if fork >= T2 else TRANSFER
def role_recipient():      return RECIPIENT      if fork >= T2 else TRANSFER
def role_mint_recipient(): return MINT_RECIPIENT if fork >= T2 else TRANSFER
```

### 3.2 Storage layout

| Slot | Field | Type |
|---|---|---|
| 0 | `policyIdCounter` | `uint64` (bytes 0..7 of the word) |
| 1 | `policyRecords` | `mapping(uint64 => PolicyRecord)` |
| 2 | `policySet` | `mapping(uint64 => mapping(address => bool))` |
| 3 | `receivePolicies` (from T6) | `mapping(address => ReceivePolicy)` |
| 4 | `tokenTransferPolicies` (from T9) | `mapping(address => TokenTransferPolicy)` |

`PolicyRecord` occupies two words at `r = mslot(policyId, 1)`:

| Word | Field | Byte offset | Size |
|---|---|---|---|
| `r + 0` (PolicyData) | `policyType` (u8) | 0 | 1 |
| | `admin` (address) | 1 | 20 |
| `r + 1` (CompoundPolicyData) | `senderPolicyId` (u64) | 0 | 8 |
| | `recipientPolicyId` (u64) | 8 | 8 |
| | `mintRecipientPolicyId` (u64) | 16 | 8 |

That is, `word(r) = policyType | admin << 8` and `word(r+1) = sender | recipient << 64 | mintRecipient << 128`. The compound word is written only for compound policies.

`policySet[id][account]` is the word at `mslot(account, mslot(id, 2))`, holding 1 (member) or 0. For a whitelist, membership means allowed; for a blacklist, restricted.

`ReceivePolicy` occupies two words at `q = mslot(account, 3)`:

| Word | Field | Byte offset | Size |
|---|---|---|---|
| `q + 0` (config) | `hasReceivePolicy` (bool) | 0 | 1 |
| | `senderPolicyId` (u64) | 1 | 8 |
| | `senderPolicyType` (u8) | 9 | 1 |
| | `tokenFilterId` (u64) | 10 | 8 |
| | `tokenFilterType` (u8) | 18 | 1 |
| | `recoveryMode` (u8: 0 Originator, 1 Receiver, 2 ThirdParty) | 19 | 1 |
| `q + 1` | `recoveryAddress` (address) | 0 | 20 |

`word(q) = has | senderPolicyId << 8 | senderPolicyType << 72 | tokenFilterId << 80 | tokenFilterType << 144 | recoveryMode << 152`. The cached type fields hold the referenced policy's `policyType` at configuration time; for built-in ids they hold the id itself (0 for policy 0, 1 for policy 1). `recoveryAddress` is written on every `setReceivePolicy`: the third-party address in ThirdParty mode, otherwise 0.

> **Resolved conflict C-T403-01**: TIP-1028 specifies two mappings (`addressReceiveConfig`, `addressRecoveryAuthority`) and a bit-level config packing that differ from this layout. Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-01).

`TokenTransferPolicy` occupies one word at `mslot(token, 4)`: `policyId` (u64) at byte offset 0 and `isSet` (bool) at byte offset 8, i.e. `word = policyId | isSet << 64`. A zero word means unset; `isSet = 1, policyId = 0` is an explicit binding to policy 0.

**Counter.** The effective counter is `counter() = max(sload(REGISTRY, 0) & (2^64 - 1), 2)` (one `sload`). It is the next id to assign. Mainnet genesis leaves slot 0 at zero, so the first policy gets id 2 and the slot then holds 3.

**Policy existence.** Policy `p` exists iff `p ∈ {0, 1}` or `p < counter()`. Policies are never deleted. A policy's `policyType` is never changed after creation (receive policies rely on the cached type).

### 3.3 Policy type decoding

```python
def decode_policy_type(t: u8) -> int:
    if t == WHITELIST or t == BLACKLIST:
        return t
    if t == COMPOUND and fork >= T2:
        return COMPOUND
    if fork >= T2:
        revert(InvalidPolicyType())
    revert(Panic(0x11))      # before T2: COMPOUND (2) and every other value
```

Stored types are always 0, 1, 2 or 255. Type 255 ("legacy invalid") can only have been written before T2 (section 3.5.5). Type 2 is only written from T2, by `createCompoundPolicy`.

**Policy lookup error.** Some callers (StablecoinDEX `cancelStaleOrder`, see precompiles/stablecoin-dex.md) treat a failed lookup specially. An error is a *policy lookup error* iff, from T2, it is `InvalidPolicyType()` or `PolicyNotFound()`; before T2, it is `Panic(0x11)`.

### 3.4 Internal operations

These are the operations other chapters call. Storage accesses are in order.

```python
def read_policy_data(p) -> (u8, address):
    w = sload(REGISTRY, mslot(p, 1))
    return (w & 0xff, (w >> 8) & (2**160 - 1))

def get_policy_data(p) -> (u8, address):
    (t, admin) = read_policy_data(p)
    # From T2: an all-zero record is checked against the counter (extra sload only then).
    if fork >= T2 and t == 0 and admin == 0 and p >= counter():
        revert(PolicyNotFound())
    return (t, admin)
```

Before T2 an unknown id (and the built-ins, when read) yields `(WHITELIST, 0)` without error.

```python
def is_authorized_simple_inner(p, user, t) -> bool:
    in_set = sload(REGISTRY, mslot(user, mslot(p, 2))) != 0   # read BEFORE decoding the type
    ty = decode_policy_type(t)
    if ty == WHITELIST: return in_set
    if ty == BLACKLIST: return not in_set
    revert(IncompatiblePolicyType())    # COMPOUND: unreachable on valid state

def is_authorized_simple(p, user, cached_type=None) -> bool:
    if p == ALLOW_ALL_POLICY_ID: return True
    if p == REJECT_ALL_POLICY_ID: return False
    t = cached_type if cached_type is not None else get_policy_data(p)[0]
    return is_authorized_simple_inner(p, user, t)

def is_authorized_as(p, user, role) -> bool:
    if always_authorized(user):              # From T6; no storage access
        return True
    if p == ALLOW_ALL_POLICY_ID: return True
    if p == REJECT_ALL_POLICY_ID: return False
    (t, _) = get_policy_data(p)
    if t == COMPOUND:
        w = sload(REGISTRY, mslot(p, 1) + 1)
        s_id, r_id, m_id = w & M64, (w >> 64) & M64, (w >> 128) & M64
        if role == SENDER:         return is_authorized_simple(s_id, user)
        if role == RECIPIENT:      return is_authorized_simple(r_id, user)
        if role == MINT_RECIPIENT: return is_authorized_simple(m_id, user)
        # TRANSFER
        s = is_authorized_simple(s_id, user)
        if fork >= T2 and not s:
            return False                     # short-circuit: recipient sub-policy not read
        r = is_authorized_simple(r_id, user)
        return s and r
    return is_authorized_simple_inner(p, user, t)
```

Notes:

- For a simple policy every role gives the same result and the policy is evaluated once.
- The `policySet` slot is read before the type is decoded, so a legacy type-255 policy costs that `sload` before it reverts.
- Sub-policy evaluation uses `get_policy_data` for the sub-policy (its record word, plus the counter if that word is zero).
- The T6 guard bypass applies to every policy id, including 0, unknown ids (no `PolicyNotFound`) and type-255 policies, and to every role. It applies only in `is_authorized_as`; receive-policy checks (`check_receive_policy`) do not use it.

> **Resolved conflict C-T403-04**: the docs state that policy 0 rejects every address and TIP-1015 that unknown ids revert, but from T6 the guard address is authorized by every policy. Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-04).

> **Resolved conflict C-T403-09**: TIP-1015's pseudo-code and cost claim ("1 keccak + 2 SLOADs") do not match the storage-access sequence above. Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-09).

```python
def receive_policy_recovery(account, mode) -> address:
    if mode == ORIGINATOR: return 0x0
    if mode == RECEIVER:   return account
    return sload(REGISTRY, mslot(account, 3) + 1) & (2**160 - 1)    # THIRD_PARTY

def check_receive_policy(token, sender, receiver) -> None | (reason, recovery):
    # From T6 only (callers gate it). No guard bypass, no policy existence check.
    c = sload(REGISTRY, mslot(receiver, 3))
    if (c & 0xff) == 0:                        # hasReceivePolicy == false
        return None
    sender_id   = (c >> 8)   & M64; sender_ty = (c >> 72)  & 0xff
    filter_id   = (c >> 80)  & M64; filter_ty = (c >> 144) & 0xff
    mode        = (c >> 152) & 0xff
    if not is_authorized_simple(filter_id, token, cached_type=filter_ty):
        return (TOKEN_FILTER, receive_policy_recovery(receiver, mode))
    if not is_authorized_simple(sender_id, sender, cached_type=sender_ty):
        return (RECEIVE_POLICY, receive_policy_recovery(receiver, mode))
    return None
```

The token filter is checked first: when both would reject, the reason is `TOKEN_FILTER` and the sender policy is not read. The recovery word `q + 1` is read only when the inbound is blocked and the mode is ThirdParty. Policy types come from the cached config bytes, so the referenced policy's record is not read.

Token-binding operations (T9) are in section 3.6.

### 3.5 External functions

Each function below runs after the framework's input charge and dispatch. `sender` is the caller (`msg.sender` of the precompile call).

#### 3.5.1 policyIdCounter()

Returns `counter()` (one `sload` of slot 0).

#### 3.5.2 policyExists(policyId)

```python
if policyId in (0, 1): return True        # no storage access
return policyId < counter()
```

#### 3.5.3 policyData(policyId)

```python
if fork >= T2:
    if policyId in (0, 1):
        return (policyId, 0x0)            # 0 -> WHITELIST, 1 -> BLACKLIST; no storage access
else:
    if not policyExists(policyId):        # built-ins: no access; others: sload counter
        revert(PolicyNotFound())
(t, admin) = get_policy_data(policyId)    # from T2 may sload the counter and revert PolicyNotFound
return (decode_policy_type(t), admin)
```

Before T2 the built-ins are read from (empty) storage and return `(WHITELIST, 0)` for both 0 and 1. From T2, a compound policy returns `(COMPOUND, 0)` and a legacy type-255 policy reverts `InvalidPolicyType()`. Before T2 a type-255 policy reverts `Panic(0x11)`.

#### 3.5.4 isAuthorized / isAuthorizedSender / isAuthorizedRecipient / isAuthorizedMintRecipient

Return `is_authorized_as(policyId, user, role)` with role `TRANSFER`, `SENDER`, `RECIPIENT`, `MINT_RECIPIENT` respectively. The directional selectors exist from T2.

Before T2, `isAuthorized` on an id that does not exist returns `false` after reading the empty record and the `policySet` slot (the record decodes as a whitelist with no members). From T2 it reverts `PolicyNotFound()`, unless the guard bypass applies.

> **Resolved conflict C-T403-05**: docs say an unknown policy id reverts with `PolicyNotFound`, without the T2 boundary. Decided: this spec follows the implementation, and the docs are fixed in [tempoxyz/docs#1098](https://github.com/tempoxyz/docs/pull/1098). See [conflicts](../conflicts.md#c-t403-05).

#### 3.5.5 createPolicy(admin, policyType)

```python
t = ensure_is_simple(policyType)
id = counter()                                          # sload slot 0
if id == 2**64 - 1: revert(Panic(0x11))
sstore(REGISTRY, 0, id + 1)
write_struct_word(REGISTRY, mslot(id, 1), policyType=t, admin=admin)
emit(REGISTRY, PolicyCreated(id, sender, t))
emit(REGISTRY, PolicyAdminUpdated(id, sender, admin))
return id

def ensure_is_simple(policyType) -> u8:
    if policyType in (WHITELIST, BLACKLIST): return policyType
    # COMPOUND or INVALID
    if fork >= T2: revert(IncompatiblePolicyType())
    return INVALID_TYPE                                  # 255 is stored before T2
```

`admin` is not validated (it may be zero or a virtual address). Before T2, requesting COMPOUND or an out-of-range type succeeds, stores type 255 and emits `PolicyCreated(…, 255)`. Such a policy exists, but every later operation that decodes its type reverts.

#### 3.5.6 createPolicyWithAccounts(admin, policyType, accounts)

```python
t = ensure_is_simple(policyType)
if fork >= T3:
    for a in accounts:                                   # no storage access
        if is_virtual(a): revert(VirtualAddressNotAllowed())
id = counter()
if id == 2**64 - 1: revert(Panic(0x11))
sstore(REGISTRY, 0, id + 1)
write_struct_word(REGISTRY, mslot(id, 1), policyType=t, admin=admin)
for a in accounts:                                       # input order; duplicates processed again
    sstore(REGISTRY, mslot(a, mslot(id, 2)), 1)
    if policyType == WHITELIST:   emit(REGISTRY, WhitelistUpdated(id, sender, a, True))
    elif policyType == BLACKLIST: emit(REGISTRY, BlacklistUpdated(id, sender, a, True))
    else: revert(IncompatiblePolicyType())               # only reachable before T2
emit(REGISTRY, PolicyCreated(id, sender, t))
emit(REGISTRY, PolicyAdminUpdated(id, sender, admin))
return id
```

The per-account events come **before** `PolicyCreated` and `PolicyAdminUpdated`. Before T2, an invalid type with a non-empty `accounts` reverts `IncompatiblePolicyType()` after the first membership write. With an empty list it succeeds as in 3.5.5. `is_virtual` is defined in section 5.1.

> **Resolved conflict C-T403-06**: the docs list `PolicyCreated` and `PolicyAdminUpdated` before the membership events. Decided: this spec follows the implementation, and the docs are fixed in [tempoxyz/docs#1098](https://github.com/tempoxyz/docs/pull/1098). See [conflicts](../conflicts.md#c-t403-06).

#### 3.5.9 createCompoundPolicy(senderPolicyId, recipientPolicyId, mintRecipientPolicyId) — from T2

### 3.6 Token transfer-policy binding (TIP-1092) — from T9

From T9 the registry can hold a token's active transfer-policy id in `tokenTransferPolicies` (slot 4, section 3.2). The legacy location is the TIP-20 token's own `transferPolicyId` field: storage slot 7 of the token account, `uint64` at byte offset 20 (packed after `nextQuoteToken`); see precompiles/tip20.md.

Internal operations:

```python
def registered_token_transfer_policy_id(token) -> None | u64:
    w = sload(REGISTRY, mslot(token, 4))
    return (w & M64) if ((w >> 64) & 0xff) != 0 else None

def set_token_transfer_policy(token, p):
    sstore(REGISTRY, mslot(token, 4), p | 1 << 64)       # single-word struct, T9 > T4: no prior sload
```

**Effective policy (normative summary of precompiles/tip20.md).** From T9 a TIP-20 token's effective transfer policy is `registered_token_transfer_policy_id(token)` if set, otherwise the legacy field (a second `sload`, of token slot 7). Before T9 it is the legacy field only. From T9:

- token creation calls `set_token_transfer_policy(token, 1)` and does **not** write the legacy field;
- `changeTransferPolicyId(p)` calls `set_token_transfer_policy(token, p)` and neither reads nor clears the legacy field.

Before T9 both write the legacy field.

> **Resolved conflict C-T403-11**: the docs describe token creation as registering a TIP-403 binding without saying this starts at T9. Decided: this spec follows the implementation, and the docs are fixed in [tempoxyz/docs#1098](https://github.com/tempoxyz/docs/pull/1098). See [conflicts](../conflicts.md#c-t403-11).

#### 3.6.1 tokenTransferPolicyId(token)

#### 3.6.2 migrateTransferPolicyIds(tokens)

Callable by anyone.

```python
migrated = 0
for token in tokens:                          # in order; duplicates are processed again
    if not has_tip20_prefix(token): continue
    if not account_code_check(token): continue
    if registered_token_transfer_policy_id(token) is not None: continue   # legacy not read
    w = sload(token, 7)
    p = (w >> 160) & M64
    set_token_transfer_policy(token, p)
    # delete the packed legacy field: read-modify-write of token slot 7
    w2 = sload(token, 7)
    sstore(token, 7, w2 & ~(M64 << 160))       # nextQuoteToken (bytes 0..19) preserved
    migrated += 1
return migrated                                 # uint256
```

No event is emitted. A duplicate token in the same call is skipped the second time because its binding now exists.

### 3.7 Fork history of the registry

| Fork | Change |
|---|---|
| Genesis | Simple policies, built-ins 0/1, `isAuthorized` only. Unknown ids are not rejected (read as an empty whitelist). Invalid `policyType` on creation stores 255. Bad stored types revert `Panic(0x11)`. `policyData(0/1)` returns `(WHITELIST, 0)`. Every role is `TRANSFER`. |
| T2 | Compound policies and directional selectors. `get_policy_data` reverts `PolicyNotFound` for zero records at ids ≥ counter. Creation rejects non-simple types with `IncompatiblePolicyType`. Bad stored types revert `InvalidPolicyType`. `policyData(0/1)` is virtual. Compound `TRANSFER` short-circuits. Directional roles are used by callers. |
| T3 | `createPolicyWithAccounts` and `modifyPolicy*` reject virtual addresses. |
| T4 | Struct-word writes no longer read the slot first (section 1). |
| T6 | Receive policies (slot 3, three selectors). The guard address is always authorized. |
| T9 | Token bindings (slot 4, two selectors). |
| T11 | Strict ABI decoding of arguments (framework); out-of-range `policyType` words fail decoding. |

### 4.3 Receipt

```solidity
enum InboundKind { TRANSFER, MINT }          // uint8
struct ClaimReceiptV1 {
    uint8   version;          // = 1
    address token;
    address recoveryAuthority;
    address originator;
    address recipient;        // literal 'to' at the TIP-20 entrypoint (may be virtual)
    uint64  blockedAt;        // block timestamp
    uint64  blockedNonce;
    uint8   blockedReason;    // TOKEN_FILTER (1) or RECEIVE_POLICY (2)
    InboundKind kind;
    bytes32 memo;
}
```

**Encoding.** `encode(receipt)` is the Solidity ABI encoding of the static tuple: exactly 10 words (320 bytes), each field right-aligned in its word (`memo` is the full word). This is the `receipt` value in `TransferBlocked` and the key preimage:

`receiptKey = keccak256(encode(receipt))`, computed with `keccak_charged` (90 gas for 320 bytes).

**Decoding** (`decode_receipt(bytes)`), used by all three entry points, is a non-validating ABI decode, the same at every fork:

- fewer than 320 bytes: `revert(InvalidReceipt())`;
- bytes after the first 320 are ignored;
- each field is taken from the low-order bytes of its word (address: low 20 bytes; `uint64`: low 8; `uint8`: low byte), and higher bytes are ignored;
- `kind`: low byte 0 → TRANSFER, 1 → MINT, anything else → the out-of-range value 255;
- `version` and `blockedReason` are not checked.

The key is always recomputed from the **re-encoded** decoded struct. A non-canonical or wrong-version witness therefore maps to a key with no stored amount, which leads to `InvalidReceipt()` where an amount is required.

**Receiver.** `resolve_receipt(bytes)`:

```python
def resolve_receipt(bytes):
    r = decode_receipt(bytes)                                   # InvalidReceipt
    try:
        receiver = resolve_recipient(r.recipient)               # section 5.4; sload if virtual
    except VirtualAddressUnregistered:
        revert(InvalidClaimAddress())
    if r.recoveryAuthority == 0x0:          mode = ORIGINATOR
    elif r.recoveryAuthority == receiver:   mode = RECEIVER
    else:                                   mode = THIRD_PARTY
    return (r, receiver, mode)

def authority(mode, r):        return r.originator if mode == ORIGINATOR else r.recoveryAuthority
def policy_subject(mode, r, receiver): return r.originator if mode == ORIGINATOR else receiver
def is_reroute(mode, to, receiver):    return True if mode == ORIGINATOR else to != receiver
def spending_account(mode, auth):      return auth if mode in (ORIGINATOR, RECEIVER) else None
```

### 4.4 storeBlocked (internal, called by TIP-20)

The TIP-20 divert (precompiles/tip20.md) first moves the funds to `GUARD` (a transfer `from → GUARD` or a mint to `GUARD` with its `Mint` event), then calls:

```python
def store_blocked(token, originator, to: Recipient, recovery, amount, reason, kind, memo):
    if reason not in (TOKEN_FILTER, RECEIVE_POLICY) or kind not in (TRANSFER, MINT):
        revert(InvalidReceipt())                         # unreachable from TIP-20
    receiver  = to.target                                # resolved master if virtual
    recipient = to.virtual_addr if to.virtual_addr else to.target
    n = max(sload(GUARD, 0) & M64, 1)
    if n == 2**64 - 1: revert(Panic(0x11))
    sstore(GUARD, 0, n + 1)
    blocked_at = min(block.timestamp, 2**64 - 1)
    r = ClaimReceiptV1(1, token, recovery, originator, recipient, blocked_at, n, reason, kind, memo)
    key = keccak_charged(encode(r))
    sstore(GUARD, mslot(key, 1), amount)                 # amount may be 0
    emit(GUARD, TransferBlocked(token, receiver, n, amount, 1, encode(r)))
    return (n, blocked_at)
```

`recovery` is the value returned by `check_receive_policy`: 0 for Originator mode, the receiver for Receiver mode, the stored address for ThirdParty mode. For transfers `originator` is the token owner `from`; for mints it is the minting caller. A zero-amount blocked inbound creates a receipt whose stored amount is 0, so it can never be claimed or burned (`InvalidReceipt()`).

There is no external entry point to `store_blocked`.

### 4.5 balanceOf(receipt)

```python
r = decode_receipt(receipt)                    # InvalidReceipt
return sload(GUARD, mslot(keccak_charged(encode(r)), 1))
```

The receipt's recipient is not resolved. Unknown, consumed or malformed-but-decodable receipts return 0.

### 4.6 claim(to, receipt)

```python
if to == GUARD: revert(InvalidClaimAddress())
(r, receiver, mode) = resolve_receipt(receipt)            # InvalidReceipt / InvalidClaimAddress
auth = authority(mode, r)
if auth != sender: revert(UnauthorizedClaimer())
key = keccak_charged(encode(r))
amount = sload(GUARD, mslot(key, 1))
if amount == 0: revert(InvalidReceipt())
sstore(GUARD, mslot(key, 1), 0)                           # consumed BEFORE the release
if not has_tip20_prefix(r.token): revert(TIP20.InvalidToken())   # unreachable for a live receipt
release_blocked_funds(r.token, r.originator, receiver, to, amount, mode, auth)
emit(GUARD, ReceiptClaimed(r.token, receiver, r.blockedNonce, r.blockedAt, r.version,
                           r.originator, r.recipient, r.recoveryAuthority, sender, to, amount))
```

`release_blocked_funds` runs in token `T = r.token` (operation names per precompiles/tip20.md):

```python
def release_blocked_funds(T, originator, receiver, to, amount, mode, auth):
    T.check_not_paused()                                   # ContractPaused
    dest = T.Recipient.resolve(to)                         # VirtualAddressUnregistered for unregistered virtual 'to'
    dest.validate()                                        # InvalidRecipient if dest.target is 0 or has the TIP-20 prefix
    if is_reroute(mode, to, receiver):
        subj = originator if mode == ORIGINATOR else receiver   # policy subject
        T.ensure_transfer_authorized(subj, dest.target)    # effective policy read once; sender role, then
                                                           # (T2+ only if sender passed) recipient role; PolicyForbids
        if check_receive_policy(T, subj, dest.target) is not None:
            revert(TIP20.PolicyForbids())                  # never diverts again
        acct = spending_account(mode, auth)
        if acct is not None:
            T.check_and_update_spending_limit(acct, amount)   # AccountKeychain, precompiles/account-keychain.md
    else:                                                  # resume: Receiver/ThirdParty mode and to == receiver
        T.ensure_authorized_as([(dest.target, role_recipient())])   # PolicyForbids
    T._transfer(GUARD, dest, amount)                       # emits Transfer(GUARD, to_literal, amount)
    if dest.virtual_addr:
        emit(T, Transfer(dest.virtual_addr, dest.target, amount))   # second hop
```

Notes:

- A resume never checks the receive policy or the spending limit, and checks only the recipient role. Every Originator-mode claim is a reroute, even to the receiver.
- `to` is compared literally with the resolved `receiver`: a claim to one of the receiver's virtual addresses is a reroute.
- `ReceiptClaimed.to` is the literal `to`.
- A release of a blocked mint emits no `Mint` event.

> **Resolved conflict C-T403-07**: TIP-1028 says a reroute to an unresolvable virtual `to` reverts `InvalidClaimAddress()`; the code reverts `VirtualAddressUnregistered()`. Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-07).

> **Resolved conflict C-T403-08**: TIP-1028 says the release emits `Transfer(GUARD, to)` followed by `ReceiptClaimed`; for a virtual `to` a second-hop `Transfer` sits between them. Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-08).

Log order of a successful claim: `Transfer(GUARD, to)` [, `Transfer(to, master)` if `to` is virtual] (from the token), then `ReceiptClaimed` (from the guard).

### 4.7 burnBlockedReceipt(receipt)

```python
(r, receiver, mode) = resolve_receipt(receipt)             # InvalidReceipt / InvalidClaimAddress
key = keccak_charged(encode(r))
amount = sload(GUARD, mslot(key, 1))
if amount == 0: revert(InvalidReceipt())
owner = policy_subject(mode, r, receiver)
if not has_tip20_prefix(r.token): revert(TIP20.InvalidToken())
T.burn_blocked(sender, owner, amount, check_protected=False)
sstore(GUARD, mslot(key, 1), 0)                            # consumed AFTER the burn
emit(GUARD, ReceiptBurned(r.token, receiver, r.blockedNonce, r.blockedAt, r.version,
                          r.originator, r.recipient, r.recoveryAuthority, sender, amount))
```

`burn_blocked(caller, owner, amount, check_protected=False)` is the TIP-20 operation of precompiles/tip20.md with these steps:

1. `check_not_paused` (from T3, so always here): `ContractPaused`.
2. `caller` holds `BURN_BLOCKED_ROLE` on the token: else `Unauthorized`.
3. The protected-address check is skipped.
4. If `is_authorized_as(effective_policy, owner, role_sender())`: `PolicyForbids`.
5. `_transfer(GUARD, 0x0, amount)` emits `Transfer(GUARD, 0, amount)`.
6. Total supply decreases by `amount`.
7. `BurnBlocked(owner, amount)` is emitted from the token.

The caller need not be the recovery authority. Log order: `Transfer(GUARD, 0x0)`, `BurnBlocked(owner)` (token), `ReceiptBurned` (guard).

### 4.8 Invariants (informative)

For every TIP-20 token T, `T.balances[GUARD]` equals the sum of `balances[key]` over the open receipts of T. The supporting rules:

- inbounds addressed to `GUARD` revert `AddressReserved()` (precompiles/tip20.md);
- `burnBlocked` with `from = GUARD` reverts `ProtectedAddress()`;
- funds leave the guard only through 4.6 and 4.7.

|---|---|---|
| 0 | `data` | `mapping(bytes4 masterId => RegistryData)` |

The entry for `masterId` is at `mslot(masterId, 0) = keccak256(0x00…00 (28 bytes) ‖ masterId ‖ uint256_be(0))`, with the key **left-padded**. The value word is `masterAddress | reserved << 160 | masterType << 248`: `masterAddress` at bytes 0..19 (low-order), 11 reserved bytes (always 0) and `masterType` (always 0) in the most significant byte. Only the address field is interpreted: an entry is registered iff `masterAddress != 0`.

> **Resolved conflict C-T403-03**: TIP-1022 gives the slot as `keccak256(abi.encode(masterId, REGISTRY_SLOT))`, which right-pads the `bytes4` key; the code left-pads it (precompiles/00-framework.md §6.5). Decided: this spec follows the implementation, and the TIP is amended in its own PR (tempoxyz/tempo#8940 to #8974). See [conflicts](../conflicts.md#c-t403-03).

### 5.4 Functions

```python
def get_master(mid) -> None | address:
    w = sload(ADDRESS_REGISTRY, mslot(mid, 0))
    a = w & (2**160 - 1)
    return None if a == 0 else a

def register_virtual_master(sender, salt):
    if not is_valid_master(sender): revert(InvalidMasterAddress())
    h = keccak256(sender (20 bytes) ‖ salt (32 bytes))    # NOT gas-charged
    if h[0:4] != b"\x00\x00\x00\x00": revert(ProofOfWorkFailed())
    mid = h[4:8]
    existing = get_master(mid)                              # sload
    if existing is not None: revert(MasterIdCollision(existing))   # also when existing == sender
    write_struct_word(ADDRESS_REGISTRY, mslot(mid, 0), masterAddress=sender, reserved=0, masterType=0)
    emit(ADDRESS_REGISTRY, MasterRegistered(mid, sender))
    return mid

def resolve_recipient(to) -> address:     # also the internal operation used by TIP-20 and the guard
    if fork < T3: return to               # before T3: no virtual-address semantics, no access
    d = decode_virtual(to)
    if d is None: return to
    m = get_master(d[0])                  # sload
    if m is None: revert(VirtualAddressUnregistered())
    return m
```

- `getMaster(mid)` returns `get_master(mid)` or `0x0`.
- `resolveRecipient(to)` returns `resolve_recipient(to)`.
- `resolveVirtualAddress(a)` returns `0x0` when `a` is not virtual (no access). Otherwise it returns `get_master(masterId)` or `0x0`; it never reverts.
- `isVirtualAddress(a)` returns `is_virtual(a)`.
- `decodeVirtualAddress(a)` returns `(true, a[0:4], a[14:20])`, or `(false, 0, 0)` when `a` is not virtual.
- `isImplicitlyApproved(a)` (from T5) returns `a ∈ IMPLICIT_APPROVAL_LIST`.

Registrations are permanent: there is no update or delete. `registerVirtualMaster` performs exactly one `sload` before the write. Before T4 (that is, at T3) `write_struct_word` adds a second, warm `sload` of the same slot.

**Implicit approval list (TIP-1035).** From T5, `IMPLICIT_APPROVAL_LIST = [0xfeec000000000000000000000000000000000000 (TipFeeManager), 0xdec0000000000000000000000000000000000000 (StablecoinDEX), 0x4D50500000000000000000000000000000000000 (TIP20ChannelReserve)]`. Before T5 the list is empty: the internal predicate returns false for every address, and the selector is not dispatched. TIP-20 `systemTransferFrom` uses the predicate (precompiles/tip20.md).

### 5.5 Use by other precompiles

From T3, TIP-20 resolves every recipient through `resolve_recipient` before pause, recipient-validity and TIP-403 checks, and evaluates policies and receive policies against the resolved master. The TIP-403 configuration functions reject virtual members (section 3.5.6, 3.5.8) and virtual receive-policy callers or recovery authorities (3.5.11). The literal virtual address never holds a TIP-20 balance from T3. Event sequences for virtual recipients are in precompiles/tip20.md.
